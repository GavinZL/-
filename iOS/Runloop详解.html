深入理解iOS/Swift中的Runloop运行循环

一、概念与背景

1.1 什么是Runloop？

RunLoop（运行循环）是iOS/macOS中管理线程生命周期与事件处理的核心机制，其本质是一个基于事件驱动的无限循环，负责在「有任务时执行任务，无任务时休眠」的循环逻辑。

核心作用：
  • 线程保活：防止线程执行完任务后立即退出，保持活跃状态以响应后续事件
  • 资源优化：无任务时休眠，避免CPU空转浪费资源
  • 事件分发：统一管理和分发各种事件源（触摸、定时器、网络等）

1.2 为什么需要Runloop？

在没有Runloop的情况下，线程的生命周期模型如下：

// 普通线程模型
Thread *thread = [[Thread alloc] init];
[thread start];  // 执行完任务后线程立即退出

void threadFunction() {
    // 执行任务
    doSomething();
    // 线程退出
}

这种模型存在以下问题：

  • 线程无法响应后续事件
  • 需要频繁创建销毁线程，资源开销大
  • 无法实现持续的事件监听

Runloop的引入解决了这些问题：

// 有Runloop的线程模型
void runloopThread() {
    while (true) {
        // 等待事件
        Event event = waitForEvent();
        
        // 处理事件
        if (event) {
            handleEvent(event);
        } else {
            // 无事件时休眠
            sleep();
        }
    }
}

1.3 Runloop的层次结构

Runloop层次体系 ├── Foundation层（NSRunloop） │ └── 基于CFRunloop的面向对象封装 │ └── Core Foundation层（CFRunloop） ├── 开源实现（可查看源码） ├── 基于C语言实现 └── 提供底层API
两层API关系：
  • NSRunLoop：OC面向对象封装，线程安全，易用性高
  • CFRunLoopRef：底层C语言实现，性能更高，功能更完整
  • 可通过NSRunLoop.getCFRunLoop()获取底层对象

二、核心机制与实现原理

2.1 Runloop的核心组成（MECE分析）

Runloop由以下五大核心组件构成：

2.1.1 CFRunLoopRef（Runloop对象）

每个线程都有唯一对应的Runloop对象：

// 源码结构（简化版）
struct __CFRunLoop {
    pthread_t _pthread;              // 对应的线程
    CFMutableSetRef _commonModes;    // 通用模式集合
    CFMutableSetRef _commonModeItems;// 通用模式项
    CFRunLoopModeRef _currentMode;   // 当前运行模式
    CFMutableSetRef _modes;          // 所有模式集合
};
// 获取Runloop对象
// 主线程Runloop（自动创建并启动）
let mainRunloop = RunLoop.main
let cfMainRunloop = CFRunLoopGetMain()

// 当前线程Runloop（懒加载创建）
let currentRunloop = RunLoop.current
let cfCurrentRunloop = CFRunLoopGetCurrent()
注意：主线程的Runloop在应用启动时自动创建并运行，子线程的Runloop需要手动获取（首次获取时自动创建）和启动。

2.1.2 CFRunLoopModeRef（运行模式）

Mode定义了Runloop在特定场景下处理哪些事件源：

// 源码结构
struct __CFRunLoopMode {
    CFStringRef _name;            // 模式名称
    CFMutableSetRef _sources0;    // Source0事件集合
    CFMutableSetRef _sources1;    // Source1事件集合
    CFMutableArrayRef _observers; // 观察者集合
    CFMutableArrayRef _timers;    // 定时器集合
};
模式名称 说明 应用场景
NSDefaultRunLoopMode 默认模式，空闲状态 App正常运行时的大部分时间
UITrackingRunLoopMode UI追踪模式 ScrollView滚动、手势追踪时
NSRunLoopCommonModes 通用模式标记（伪模式） 将事件添加到多个模式中
UIInitializationRunLoopMode 初始化模式 App启动时的私有模式
GSEventReceiveRunLoopMode 系统事件接收模式 接收系统内部事件
重要特性：
  • Runloop每次只能运行在一个Mode下
  • 切换Mode需要退出当前循环，重新进入
  • CommonModes是一个标记，包含Default和Tracking模式

2.1.3 CFRunLoopSourceRef（事件源）

事件源分为两类：

Source0（非基于Port的事件）
  • 触摸事件处理
  • performSelector系列方法
  • 需要手动唤醒Runloop
// Source0源码结构
struct __CFRunLoopSource {
    CFRunLoopSourceContext context; // 回调函数上下文
    void (*perform)(void *info);    // 执行回调
};
Source1（基于Port的事件）
  • 系统底层通过mach_port通信的事件
  • 可以主动唤醒Runloop
  • 用于线程间通信
// Source1示例：线程间通信
class ThreadCommunication {
    var thread: Thread?
    var runloop: CFRunLoop?
    
    func createWorkerThread() {
        thread = Thread {
            // 获取当前线程Runloop
            self.runloop = CFRunLoopGetCurrent()
            
            // 添加Source1（Port）
            let port = NSPort()
            RunLoop.current.add(port, forMode: .default)
            
            // 启动Runloop
            CFRunLoopRun()
        }
        thread?.start()
    }
    
    func sendMessageToWorker() {
        // 通过Port发送消息，会唤醒Runloop
        // Source1自动唤醒目标线程
    }
}

2.1.4 CFRunLoopTimerRef（定时器）

基于时间的触发源：

// Timer源码结构
struct __CFRunLoopTimer {
    CFAbsoluteTime _nextFireDate;  // 下次触发时间
    CFTimeInterval _interval;      // 触发间隔
    void (*_callout)(CFRunLoopTimerRef, void *); // 回调函数
};
// Swift中的Timer使用
// 1. 普通Timer（需要手动加入Runloop）
let timer = Timer(timeInterval: 1.0, repeats: true) { _ in
    print("Timer fired")
}
RunLoop.current.add(timer, forMode: .default)

// 2. 自动加入Runloop的Timer
let scheduledTimer = Timer.scheduledTimer(withTimeInterval: 1.0, repeats: true) { _ in
    print("Scheduled timer fired")
}

// 3. 添加到CommonModes（解决滚动时停止问题）
RunLoop.current.add(timer, forMode: .common)

// 4. GCD Timer（不依赖Runloop，更精准）
let gcdTimer = DispatchSource.makeTimerSource(queue: .main)
gcdTimer.schedule(deadline: .now(), repeating: 1.0)
gcdTimer.setEventHandler {
    print("GCD timer fired")
}
gcdTimer.resume()
常见问题：ScrollView滚动时Timer停止触发
原因：滚动时Runloop切换到TrackingMode，而Timer只添加在DefaultMode
解决：将Timer添加到CommonModes

2.1.5 CFRunLoopObserverRef（观察者）

监听Runloop状态变化的机制：

// Observer可监听的状态
typedef CF_OPTIONS(CFOptionFlags, CFRunLoopActivity) {
    kCFRunLoopEntry         = (1UL << 0),  // 即将进入Runloop
    kCFRunLoopBeforeTimers  = (1UL << 1),  // 即将处理Timer
    kCFRunLoopBeforeSources = (1UL << 2),  // 即将处理Source
    kCFRunLoopBeforeWaiting = (1UL << 5),  // 即将进入休眠
    kCFRunLoopAfterWaiting  = (1UL << 6),  // 刚从休眠中唤醒
    kCFRunLoopExit          = (1UL << 7),  // 即将退出Runloop
    kCFRunLoopAllActivities = 0x0FFFFFFFU  // 所有状态
};
// 添加Observer监听Runloop状态
func addRunloopObserver() {
    let observer = CFRunLoopObserverCreateWithHandler(
        kCFAllocatorDefault,
        CFRunLoopActivity.allActivities.rawValue,
        true,  // 是否重复
        0      // 优先级
    ) { observer, activity in
        switch activity {
        case .entry:
            print("即将进入Runloop")
        case .beforeTimers:
            print("即将处理Timer")
        case .beforeSources:
            print("即将处理Source")
        case .beforeWaiting:
            print("即将休眠")
        case .afterWaiting:
            print("刚唤醒")
        case .exit:
            print("即将退出")
        default:
            break
        }
    }
    
    CFRunLoopAddObserver(CFRunLoopGetCurrent(), observer, .defaultMode)
}

2.2 Runloop运行机制详解

2.2.1 完整运行流程

// Runloop核心循环伪代码
int CFRunLoopRunSpecific(CFRunLoopRef rl, CFStringRef modeName) {
    // 1. 通知Observer：即将进入Runloop
    __CFRunLoopDoObservers(rl, currentMode, kCFRunLoopEntry);
    
    do {
        // 2. 通知Observer：即将处理Timer
        __CFRunLoopDoObservers(rl, currentMode, kCFRunLoopBeforeTimers);
        
        // 3. 通知Observer：即将处理Source0
        __CFRunLoopDoObservers(rl, currentMode, kCFRunLoopBeforeSources);
        
        // 4. 处理Blocks（使用CFRunLoopPerformBlock添加的）
        __CFRunLoopDoBlocks(rl, currentMode);
        
        // 5. 处理Source0事件
        if (__CFRunLoopDoSources0(rl, currentMode)) {
            // 处理完Source0后再次处理Blocks
            __CFRunLoopDoBlocks(rl, currentMode);
        }
        
        // 6. 如果有Source1，直接处理并跳转到第9步
        if (__CFRunLoopServiceMachPort()) {
            goto handle_msg;
        }
        
        // 7. 通知Observer：即将休眠
        __CFRunLoopDoObservers(rl, currentMode, kCFRunLoopBeforeWaiting);
        
        // 8. 进入休眠，等待唤醒
        __CFRunLoopSetSleeping(rl);
        __CFRunLoopServiceMachPort(waitSet, &msg);
        __CFRunLoopUnsetSleeping(rl);
        
        // 9. 通知Observer：刚被唤醒
        __CFRunLoopDoObservers(rl, currentMode, kCFRunLoopAfterWaiting);
        
    handle_msg:
        // 10. 处理唤醒原因
        if (被Timer唤醒) {
            __CFRunLoopDoTimers(rl, currentMode);
        } 
        else if (被GCD唤醒) {
            __CFRUNLOOP_IS_SERVICING_THE_MAIN_DISPATCH_QUEUE__(msg);
        } 
        else if (被Source1唤醒) {
            __CFRunLoopDoSource1(rl, currentMode, source1);
        }
        
        // 11. 处理Blocks
        __CFRunLoopDoBlocks(rl, currentMode);
        
    } while (!stop && !timeout);
    
    // 12. 通知Observer：即将退出Runloop
    __CFRunLoopDoObservers(rl, currentMode, kCFRunLoopExit);
}

2.2.2 唤醒机制

Runloop可以被以下方式唤醒：

唤醒方式 说明 底层实现
Source1事件 基于mach_port的事件 内核发送消息到端口
Timer到期 定时器触发时间到达 内核定时器触发
外部手动唤醒 调用CFRunLoopWakeUp 向mach_port发送消息
超时退出 运行时间达到设定值 mach_msg超时返回

2.2.3 底层实现：mach_msg机制

Runloop的休眠和唤醒依赖于macOS/iOS的Mach内核机制：

// 底层休眠/唤醒实现
mach_msg_return_t mach_msg(
    mach_msg_header_t *msg,
    mach_msg_option_t option,
    mach_msg_size_t send_size,
    mach_msg_size_t rcv_size,
    mach_port_t rcv_name,
    mach_msg_timeout_t timeout,
    mach_port_t notify
);

// Runloop休眠时调用
mach_msg(
    NULL,                    // 不发送消息
    MACH_RCV_MSG,           // 接收模式
    0,                      // 发送大小
    sizeof(buffer),         // 接收缓冲区大小
    port,                   // 监听的端口
    timeout,                // 超时时间
    MACH_PORT_NULL
);
// 此调用会让线程进入内核态休眠，直到端口收到消息
休眠机制的优势：
  • 真正休眠：线程进入内核态休眠，不占用CPU资源
  • 即时响应：内核收到消息后立即唤醒线程
  • 高效能：避免轮询检查，系统资源消耗最小

三、应用场景

3.1 常驻线程（保活线程）

使用Runloop保持线程不退出，实现长期任务处理：

class PermanentThread {
    private var thread: Thread?
    private var runloop: CFRunLoop?
    
    // 创建常驻线程
    func createPermanentThread() {
        thread = Thread { [weak self] in
            // 必须添加一个Source/Timer/Observer，否则Runloop会立即退出
            // 方法1：添加一个永不触发的Port
            let port = NSPort()
            RunLoop.current.add(port, forMode: .default)
            
            // 或方法2：添加一个永不触发的Timer
            // let timer = Timer(timeInterval: Double.greatestFiniteMagnitude, 
            //                   repeats: true) { _ in }
            // RunLoop.current.add(timer, forMode: .default)
            
            // 保存Runloop引用
            self?.runloop = CFRunLoopGetCurrent()
            
            // 启动Runloop
            CFRunLoopRun()
            
            print("Runloop退出")
        }
        thread?.start()
    }
    
    // 在常驻线程执行任务
    func executeTask(_ block: @escaping () -> Void) {
        guard let thread = thread else { return }
        perform(#selector(runTask(_:)), 
                on: thread, 
                with: block, 
                waitUntilDone: false)
    }
    
    @objc private func runTask(_ block: () -> Void) {
        block()
    }
    
    // 停止常驻线程
    func stop() {
        guard let runloop = runloop else { return }
        CFRunLoopStop(runloop)
    }
}

// 使用示例
let permanentThread = PermanentThread()
permanentThread.createPermanentThread()

// 在后台线程执行耗时操作
permanentThread.executeTask {
    print("在常驻线程执行任务：\(Thread.current)")
    // 执行耗时操作
}

// 不需要时停止
// permanentThread.stop()

3.2 监控卡顿检测

利用Runloop Observer监听主线程卡顿：

class FPSMonitor {
    private var observer: CFRunLoopObserver?
    private var semaphore = DispatchSemaphore(value: 0)
    private var activity: CFRunLoopActivity = .entry
    
    func startMonitoring() {
        observer = CFRunLoopObserverCreateWithHandler(
            kCFAllocatorDefault,
            CFRunLoopActivity.allActivities.rawValue,
            true,
            0
        ) { [weak self] _, activity in
            self?.activity = activity
            self?.semaphore.signal()
        }
        
        CFRunLoopAddObserver(
            CFRunLoopGetMain(),
            observer,
            CFRunLoopMode.commonModes
        )
        
        // 在子线程监控
        DispatchQueue.global().async {
            self.monitorLoop()
        }
    }
    
    private func monitorLoop() {
        while true {
            // 等待Runloop状态变化，超时时间250ms
            let timeout = semaphore.wait(timeout: .now() + 0.25)
            
            if timeout == .timedOut {
                // 超时说明主线程卡顿
                if activity == .beforeSources || activity == .afterWaiting {
                    print("⚠️ 检测到主线程卡顿！")
                    // 记录堆栈信息
                    let callStack = Thread.callStackSymbols
                    print("堆栈：\(callStack)")
                }
            }
        }
    }
    
    func stopMonitoring() {
        if let observer = observer {
            CFRunLoopRemoveObserver(
                CFRunLoopGetMain(),
                observer,
                CFRunLoopMode.commonModes
            )
        }
    }
}

3.3 自动释放池的管理

Runloop自动创建和释放AutoreleasePool：

// Runloop与AutoreleasePool的关系
/*
主线程Runloop在每次循环中自动管理AutoreleasePool：

1. kCFRunLoopEntry（进入Runloop）
   → 创建AutoreleasePool (_objc_autoreleasePoolPush)

2. kCFRunLoopBeforeWaiting（即将休眠）
   → 释放旧的Pool (_objc_autoreleasePoolPop)
   → 创建新的Pool (_objc_autoreleasePoolPush)

3. kCFRunLoopExit（退出Runloop）
   → 释放Pool (_objc_autoreleasePoolPop)
*/

// 子线程需要手动管理
DispatchQueue.global().async {
    // 没有Runloop的子线程，需要手动创建
    autoreleasepool {
        // 创建大量临时对象
        for i in 0..<10000 {
            let data = NSData(bytes: [UInt8](repeating: 0, count: 1000), 
                            length: 1000)
            // data会被加入autoreleasepool
        }
    } // 释放pool，回收内存
}

// 如果子线程启动了Runloop
Thread.detachNewThread {
    // 手动创建第一个Pool
    autoreleasepool {
        let port = NSPort()
        RunLoop.current.add(port, forMode: .default)
        
        // Runloop会自动管理后续的AutoreleasePool
        CFRunLoopRun()
    }
}

// 界面更新机制
class ViewUpdateMechanism {

3.6 网络请求

NSURLConnection与Runloop的关系：

// NSURLConnection依赖Runloop
class NetworkWithRunloop {
    func startRequest() {
        let url = URL(string: "https://api.example.com")!
        let request = URLRequest(url: url)
        
        // NSURLConnection在当前线程的Runloop中调度
        // 必须保证Runloop在运行
        let connection = NSURLConnection(request: request, 
                                        delegate: self,
                                        startImmediately: false)
        
        // 指定Runloop模式
        connection?.schedule(in: .current, forMode: .common)
        connection?.start()
    }
    
    // 子线程中使用NSURLConnection
    func requestInBackgroundThread() {
        Thread.detachNewThread {
            let url = URL(string: "https://api.example.com")!
            let request = URLRequest(url: url)
            
            // 必须启动Runloop
            let connection = NSURLConnection(request: request, 
                                            delegate: self,
                                            startImmediately: false)
            connection?.schedule(in: .current, forMode: .default)
            connection?.start()
            
            // 启动Runloop接收回调
            CFRunLoopRun()
        }
    }
}

四、高级技巧与最佳实践

4.1 performSelector系列方法

不同的performSelector方法与Runloop的关系：

class PerformSelectorDemo: NSObject {
    func testPerformSelector() {
        // 1. 立即执行（不依赖Runloop）
        performSelector(onMainThread: #selector(task1), 
                       with: nil, 
                       waitUntilDone: false)
        
        // 2. 延迟执行（依赖Runloop）
        perform(#selector(task2), 
               with: nil, 
               afterDelay: 1.0)
        
        // 3. 在指定Runloop模式执行
        perform(#selector(task3), 
               with: nil, 
               afterDelay: 1.0,
               inModes: [.common])
        
        // 4. 取消延迟执行
        NSObject.cancelPreviousPerformRequests(withTarget: self, 
                                               selector: #selector(task2), 
                                               object: nil)
    }
    
    @objc func task1() { print("Task 1") }
    @objc func task2() { print("Task 2") }
    @objc func task3() { print("Task 3") }
    
    // 注意事项
    func warningCase() {
        // ⚠️ 子线程如果没有Runloop，perform不会执行
        Thread.detachNewThread {
            self.perform(#selector(self.task1), 
                        with: nil, 
                        afterDelay: 1.0)
            // 不会执行，因为线程没有启动Runloop
        }
        
        // ✅ 正确做法
        Thread.detachNewThread {
            self.perform(#selector(self.task1), 
                        with: nil, 
                        afterDelay: 1.0)
            // 启动Runloop
            RunLoop.current.run()
        }
    }
}

class RunloopLifecycle {
    // 启动方式1：无限循环（常用于后台线程）
    func method1_run() {
        let port = NSPort()
        RunLoop.current.add(port, forMode: .default)
        
        // 一直运行，直到调用CFRunLoopStop
        RunLoop.current.run()
        print("Runloop退出")
    }
    
    // 启动方式2：运行到指定时间
    func method2_runUntilDate() {
        let port = NSPort()
        RunLoop.current.add(port, forMode: .default)
        
        // 运行10秒后自动退出
        RunLoop.current.run(until: Date(timeIntervalSinceNow: 10))
        print("Runloop超时退出")
    }
    
    // 启动方式3：运行指定模式
    func method3_runMode() {
        let port = NSPort()
        RunLoop.current.add(port, forMode: .default)
        
        // 运行一次，处理完事件后退出
        RunLoop.current.run(mode: .default, before: Date.distantFuture)
        print("处理完一次事件")
    }
    
    // 启动方式4：CFRunLoop底层API（最灵活）
    func method4_cfRunloop() {
        let port = NSPort()
        RunLoop.current.add(port, forMode: .default)
        
        let runloop = CFRunLoopGetCurrent()
        
        // 运行指定秒数
        CFRunLoopRunInMode(.defaultMode, 10.0, false)
        
        // 或无限运行
        CFRunLoopRun()
        
        // 停止Runloop
        CFRunLoopStop(runloop)
    }
    
    // 安全退出Runloop
    class SafeRunloopThread {
        private var thread: Thread?
        private var runloop: CFRunLoop?
        private var shouldStop = false
        
        func start() {
            thread = Thread { [weak self] in
                guard let self = self else { return }
                
                let port = NSPort()
                RunLoop.current.add(port, forMode: .default)
                self.runloop = CFRunLoopGetCurrent()
                
                // 使用循环控制退出
                while !self.shouldStop {
                    // 每次运行一小段时间，检查退出标志
                    RunLoop.current.run(mode: .default, 
                                       before: Date(timeIntervalSinceNow: 0.5))
                }
                
                print("Runloop安全退出")
            }
            thread?.start()
        }
        
        func stop() {
            shouldStop = true
            if let runloop = runloop {
                CFRunLoopStop(runloop)
            }
        }
    }
}

        RunLoop.current.add(timer, forMode: .tracking)
    }
    
    // 解决方案3：使用GCD Timer
    func solution3_gcdTimer() {

        timer.schedule(deadline: .now(), repeating: 1.0)
        timer.setEventHandler {

        }
        timer.resume()

基于开源的CF-1153.18版本分析关键实现：

// CFRunLoop核心数据结构
struct __CFRunLoop {
    CFRuntimeBase _base;
    pthread_mutex_t _lock;           // 互斥锁
    __CFPort _wakeUpPort;            // 唤醒端口
    Boolean _unused;
    volatile _per_run_data *_perRunData;
    pthread_t _pthread;              // 对应线程
    uint32_t _winthread;
    CFMutableSetRef _commonModes;    // Common标记的模式集合
    CFMutableSetRef _commonModeItems;// Common标记的items
    CFRunLoopModeRef _currentMode;   // 当前模式
    CFMutableSetRef _modes;          // 所有模式
    struct _block_item *_blocks_head;// Block链表头
    struct _block_item *_blocks_tail;// Block链表尾
    CFAbsoluteTime _runTime;
    CFAbsoluteTime _sleepTime;
    CFTypeRef _counterpart;
};

// Runloop与线程的映射关系
// 全局字典存储：thread → runloop
CFMutableDictionaryRef __CFRunLoops = NULL;
CFLock_t loopsLock = CFLockInit;

CFRunLoopRef _CFRunLoopGet0(pthread_t t) {
    if (pthread_equal(t, kNilPthreadT)) {
        t = pthread_main_thread_np();
    }
    __CFLock(&loopsLock);
    
    if (!__CFRunLoops) {
        __CFUnlock(&loopsLock);
        // 第一次调用，创建字典
        CFMutableDictionaryRef dict = CFDictionaryCreateMutable(...);
        
        // 创建主线程Runloop
        CFRunLoopRef mainLoop = __CFRunLoopCreate(pthread_main_thread_np());
        CFDictionarySetValue(dict, pthread_main_thread_np(), mainLoop);
        
        __CFRunLoops = dict;
    }
    
    // 从字典获取Runloop
    CFRunLoopRef loop = (CFRunLoopRef)CFDictionaryGetValue(__CFRunLoops, t);
    __CFUnlock(&loopsLock);
    
    if (!loop) {
        // 不存在则创建
        CFRunLoopRef newLoop = __CFRunLoopCreate(t);
        __CFLock(&loopsLock);
        loop = (CFRunLoopRef)CFDictionaryGetValue(__CFRunLoops, t);
        if (!loop) {
            CFDictionarySetValue(__CFRunLoops, t, newLoop);
            loop = newLoop;
        }
        __CFUnlock(&loopsLock);
    }
    
    return loop;
}

// 休眠/唤醒的核心实现
static int32_t __CFRunLoopRun(...) {
    // ... 前面的处理
    
    // 进入休眠
    __CFRunLoopSetSleeping(rl);
    
    // 调用mach_msg等待消息
    mach_msg_return_t msg_ret = 0;
    msg_ret = mach_msg(
        msg,                    // 消息头
        MACH_RCV_MSG,          // 接收模式
        0,                     // 发送大小
        sizeof(msg_buffer),    // 接收大小
        port,                  // 监听的端口
        timeout,               // 超时时间
        MACH_PORT_NULL         // 通知端口
    );
    
    // 被唤醒
    __CFRunLoopUnsetSleeping(rl);
    
    // 根据返回值判断唤醒原因
    if (msg_ret == MACH_MSG_SUCCESS) {
        // 处理消息
    } else if (msg_ret == MACH_RCV_TIMED_OUT) {
        // 超时
    }
    
    // ... 后续处理
}

class RunloopMemoryManagement {

            CFRunLoopActivity.allActivities.rawValue,
            true,
            0

            CFRunLoopAddObserver(CFRunLoopGetCurrent(), observer, .defaultMode)

        // CFRunLoopRemoveObserver(CFRunLoopGetCurrent(), observer, .defaultMode)
    }
    
    // 线程安全的Runloop访问
    func threadSafeAccess() {

            // 使用runloop
        }

    }

// AFNetworking的常驻线程实现（简化版）
class AFNetworkingRunloopDemo {
    static let shared = AFNetworkingRunloopDemo()
    private var networkThread: Thread?
    private var networkRunloop: RunLoop?
    
    private init() {
        networkThread = Thread(target: self, 
                              selector: #selector(networkThreadMain), 
                              object: nil)
        networkThread?.name = "AFNetworking"
        networkThread?.start()
    }
    
    @objc private func networkThreadMain() {
        // 保证Runloop不退出
        let port = NSPort()
        RunLoop.current.add(port, forMode: .default)
        
        // 保存Runloop引用
        networkRunloop = RunLoop.current
        
        // 启动Runloop
        while !Thread.current.isCancelled {
            RunLoop.current.run(mode: .default, 
                               before: Date.distantFuture)
        }
    }
    
    func performTask(_ task: @escaping () -> Void) {
        guard let thread = networkThread else { return }
        
        perform(#selector(executeTask(_:)), 
               on: thread, 
               with: task, 
               waitUntilDone: false)
    }
    
    @objc private func executeTask(_ task: () -> Void) {
        task()
    }
}

// 为什么AFNetworking需要常驻线程？
/*
1. NSURLConnection的delegate回调需要在有Runloop的线程
2. 避免频繁创建销毁线程，提升性能
3. 统一管理网络请求，便于取消和控制

注意：AFNetworking 3.x以后改用NSURLSession，
不再需要常驻线程，因为URLSession基于GCD实现
*/

5.3 最佳实践总结

Runloop使用建议：
  • ✅ 主线程Runloop由系统管理，无需手动启动
  • ✅ 子线程需要长期响应事件时，使用Runloop保活
  • ✅ Timer添加到CommonModes避免滚动停止问题
  • ✅ 使用GCD Timer替代NSTimer，避免Runloop依赖
  • ⚠️ 避免在Runloop回调中执行耗时操作
  • ⚠️ 及时释放Observer和Timer，避免内存泄漏
  • ⚠️ 跨线程访问Runloop要特别小心
  • ❌ 不要在子线程使用performSelector:afterDelay:而不启动Runloop
