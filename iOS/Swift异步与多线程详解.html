📚 一、概念与背景

1.1 异步编程的演进

Swift的异步编程经历了从传统多线程到现代结构化并发的演进。Swift 5.5之前，开发者依赖GCD、Operation Queue等机制，存在回调地狱、数据竞争等问题。Swift 5.5引入async/await、Actor等特性，从语言层面提供更安全的并发编程模型。

  • Swift并发编程历史
    • 传统时代（Swift 5.5之前）
      • GCD（Grand Central Dispatch）
      • Operation & OperationQueue
      • Thread & NSLock
      • 闭包回调（Callback Hell）
    • 现代并发时代（Swift 5.5+）
      • async/await - 异步函数
      • Actor - 数据隔离
      • Task - 结构化并发
      • Sendable - 跨并发域安全
      • AsyncSequence - 异步序列

1.2 结构化并发（Structured Concurrency）

结构化并发将并发任务组织成树形结构，确保父任务在所有子任务完成前不会结束，避免任务泄漏。

结构化并发核心原则：
1. 任务层次结构：子任务继承父任务的优先级和取消状态
2. 自动取消传播：父任务取消时，所有子任务被取消
3. 错误处理：子任务错误向上传播到父任务
4. 生命周期管理：父任务等待所有子任务完成

1.3 数据竞争（Data Race）

数据竞争指多个线程同时访问同一内存位置，且至少有一个是写操作，没有适当的同步机制。Swift的Actor模型通过编译期检查和运行时隔离，从根本上消除数据竞争。

⚡ 二、async/await机制

2.1 基本概念

async关键字声明异步函数，await调用异步函数并等待结果。异步函数可以在不阻塞当前线程的情况下暂停执行，让出CPU给其他任务。

Swift - 基础异步函数
// 定义异步函数
func fetchUserData(id: Int) async throws -> User {
    let url = URL(string: "https://api.example.com/users/\(id)")!
    let (data, _) = try await URLSession.shared.data(from: url)
    return try JSONDecoder().decode(User.self, from: data)
}

// 调用异步函数
Task {
    do {
        let user = try await fetchUserData(id: 123)
        print("User: \(user.name)")
    } catch {
        print("Error: \(error)")
    }
}

2.2 底层实现原理

Swift的async/await基于协程（Coroutine）实现。编译器将异步函数转换为状态机，每个await点都是潜在的暂停点。

编译器转换过程：
1. 状态机生成：将异步函数拆分为多个片段，每个await之间是一个状态
2. Continuation创建：在暂停点创建Continuation对象，保存执行上下文
3. 任务调度：将Continuation提交到全局协作线程池
4. 恢复执行：异步操作完成后，通过Continuation恢复执行
Swift - 编译器状态机转换（伪代码）
// 原始异步函数
func processData() async -> String {
    let step1 = await fetchStep1()  // 暂停点1
    let step2 = await fetchStep2(step1)  // 暂停点2
    return combine(step1, step2)
}

// 编译器生成的状态机
enum ProcessDataState {
    case initial
    case afterStep1(String)
    case afterStep2(String, String)
}

2.3 async/await vs 传统回调

特性async/await传统回调
代码可读性线性、顺序执行风格嵌套回调、难以阅读
错误处理使用try/catch统一处理每个回调单独处理
取消机制内置取消传播需手动实现
线程安全编译器检查运行时问题
性能开销低（协作式调度）高（线程切换）

🛡️ 三、Actor模型

3.1 Actor基础

Actor是Swift 5.5引入的新引用类型，用于保护共享可变状态。Actor确保同一时间只有一个任务可以访问其可变状态，从编译器层面消除数据竞争。

Swift - Actor vs 传统Class
// ❌ 传统类存在数据竞争风险
class Counter {
    var value: Int = 0
    
    func increment() {
        value += 1  // ⚠️ 多线程访问不安全
    }
}

// ✅ Actor确保线程安全
actor SafeCounter {
    var value: Int = 0
    
    func increment() {
        value += 1  // ✅ Actor隔离，线程安全
    }
    
    func getValue() -> Int {
        return value
    }
}

// 使用Actor
let counter = SafeCounter()
await counter.increment()  // 必须使用await
let value = await counter.getValue()

3.2 Actor隔离（Actor Isolation）

Actor的属性和方法默认是隔离的，只能在Actor内部同步访问，外部必须通过await异步访问。

Swift - Actor隔离规则
actor DataManager {
    private var cache: [String: Data] = [:]
    let baseURL: URL  // immutable属性可直接访问
    
    init(baseURL: URL) {
        self.baseURL = baseURL
    }
    
    // 隔离方法 - 需要await访问
    func getData(key: String) -> Data? {
        return cache[key]
    }
    
    // 非隔离方法 - 可同步访问
    nonisolated func buildURL(path: String) -> URL {
        return baseURL.appendingPathComponent(path)
    }
}

3.3 MainActor

MainActor是全局唯一的Actor，运行在主线程上。所有UI更新必须在MainActor上执行。

Swift - MainActor三种使用方式
// 方式1: 标记整个类
@MainActor
class ViewModel: ObservableObject {
    @Published var users: [User] = []
    
    func loadUsers() async {
        let fetchedUsers = await fetchUsersFromAPI()
        users = fetchedUsers  // 自动在主线程执行
    }
}

// 方式2: 标记特定方法
@MainActor
func updateUI(data: [String]) {
    // 保证在主线程执行
}

// 方式3: 运行时切换
await MainActor.run {
    updateUILabel(data)
}
⚠️ MainActor注意事项：
• 避免在MainActor上执行耗时操作，会阻塞UI
• UIKit/AppKit的所有UI组件隐式运行在MainActor上
• @MainActor具有传染性，调用链中的函数也需要是@MainActor

🔒 四、Sendable协议

4.1 Sendable概念

Sendable协议标记了可以安全地在并发域之间传递的类型。编译器检查Sendable类型，确保不会引发数据竞争。

Swift - Sendable类型示例
// ✅ 值类型默认是Sendable
struct User: Sendable {
    let id: Int
    let name: String
}

// ✅ Actor自动是Sendable
actor DataStore {
    var data: [String: Any] = [:]
}

// ✅ final类 + 所有属性都是let + Sendable类型
final class Configuration: Sendable {
    let apiKey: String
    let timeout: TimeInterval
    
    init(apiKey: String, timeout: TimeInterval) {
        self.apiKey = apiKey
        self.timeout = timeout
    }
}

4.2 Sendable类型规则

类型分类条件示例
自动Sendable值类型，所有成员Sendablestruct、enum、Int、String
Actor所有Actoractor DataManager
final类所有属性都是let + Sendablefinal class Config
@Sendable闭包不捕获可变状态@Sendable () -> Void
不能Sendable包含可变状态的非final类class ViewModel

4.3 @unchecked Sendable

对于内部已实现线程安全但无法通过编译器检查的类型，可使用@unchecked Sendable。

Swift - 使用锁实现线程安全
final class ThreadSafeCounter: @unchecked Sendable {
    private var _value: Int = 0
    private let lock = NSLock()
    
    var value: Int {
        lock.lock()
        defer { lock.unlock() }
        return _value
    }
    
    func increment() {
        lock.lock()
        defer { lock.unlock() }
        _value += 1
    }
}
⚠️ 使用@unchecked Sendable的风险：
• 绕过了编译器的安全检查，需要手动保证线程安全
• 如果实现有误，会导致运行时数据竞争
• 应该优先使用Actor而非@unchecked Sendable

⚙️ 五、Task与结构化并发

5.1 Task基础

Task是Swift并发的基本执行单元，代表一个异步工作。Task可以创建子任务，形成任务树。

Swift - Task基本操作
// 创建Task
let task = Task {
    let result = await someAsyncOperation()
    return result
}

// 等待Task完成
let result = await task.value

// 取消Task
task.cancel()

// 检查取消状态
if Task.isCancelled {
    print("Task cancelled")
    return
}

5.3 TaskGroup - 并行任务组

Swift - 并行下载多个图片
func downloadImages(urls: [URL]) async -> [UIImage] {
    await withTaskGroup(of: UIImage?.self) { group in
        for url in urls {
            group.addTask {
                try? await downloadImage(from: url)
            }
        }
        
        var images: [UIImage] = []
        for await image in group {
            if let image = image {
                images.append(image)
            }
        }
        return images
    }
}

5.4 async let - 并发绑定

Swift - async let并发执行
// ❌ 顺序执行（慢）- 总共3秒
func loadDataSequential() async throws -> (User, [Post], [Comment]) {
    let user = try await fetchUser()
    let posts = try await fetchPosts()
    let comments = try await fetchComments()
    return (user, posts, comments)
}

// ✅ 并发执行（快）- 约1秒
func loadDataConcurrent() async throws -> (User, [Post], [Comment]) {
    async let user = fetchUser()
    async let posts = fetchPosts()
    async let comments = fetchComments()
    
    return try await (user, posts, comments)
}

5.5 Task取消

Swift的Task取消是协作式的，需要任务主动检查取消状态。

Swift - Task取消三种方式
// 方式1: 检查isCancelled
func processLargeData() async {
    for i in 1...10000 {
        if Task.isCancelled {
            return
        }
        await processItem(i)
    }
}

// 方式2: try Task.checkCancellation()
try Task.checkCancellation()  // 如果已取消，抛出CancellationError

// 方式3: withTaskCancellationHandler
try await withTaskCancellationHandler {
    try await downloadFile(url)
} onCancel: {
    print("Cleaning up...")
}
取消传播规则：
• 父Task取消时，所有子任务自动标记为取消
• 子任务需要主动检查Task.isCancelled
• TaskGroup中的任务会自动传播取消状态
• async let创建的子任务也会继承取消状态

🎯 六、应用场景

6.1 网络请求封装

Swift - Actor封装网络层
actor NetworkManager {
    static let shared = NetworkManager()
    
    func request<T: Decodable>(url: URL, type: T.Type) async throws -> T {
        let (data, response) = try await URLSession.shared.data(from: url)
        
        guard let httpResponse = response as? HTTPURLResponse,
              200...299 ~= httpResponse.statusCode else {
            throw NetworkError.invalidResponse
        }
        
        return try JSONDecoder().decode(T.self, from: data)
    }
}

// 使用
@MainActor
class ViewModel: ObservableObject {
    @Published var users: [User] = []
    
    func loadUsers() async {
        do {
            let url = URL(string: "https://api.example.com/users")!
            users = try await NetworkManager.shared.request(url: url, type: [User].self)
        } catch {
            print("Failed: \(error)")
        }
    }
}

6.2 数据缓存Actor

Swift - Actor实现缓存管理
actor CacheManager<Key: Hashable, Value> {
    private var cache: [Key: CachedValue] = [:]
    private let expirationInterval: TimeInterval
    
    struct CachedValue {
        let value: Value
        let timestamp: Date
    }
    
    init(expirationInterval: TimeInterval = 300) {
        self.expirationInterval = expirationInterval
    }
    
    func get(for key: Key) -> Value? {
        guard let cached = cache[key] else { return nil }
        
        if Date().timeIntervalSince(cached.timestamp) > expirationInterval {
            cache[key] = nil
            return nil
        }
        
        return cached.value
    }
    
    func set(_ value: Value, for key: Key) {
        cache[key] = CachedValue(value: value, timestamp: Date())
    }
}

6.3 图片加载

Swift - Actor实现图片加载器
actor ImageLoader {
    private var cache: [URL: UIImage] = [:]
    private var loadingTasks: [URL: Task<UIImage, Error>] = [:]
    
    func loadImage(from url: URL) async throws -> UIImage {
        // 检查缓存
        if let cached = cache[url] {
            return cached
        }
        
        // 检查是否正在加载
        if let existingTask = loadingTasks[url] {
            return try await existingTask.value
        }
        
        // 创建加载任务
        let task = Task {
            let (data, _) = try await URLSession.shared.data(from: url)
            guard let image = UIImage(data: data) else {
                throw ImageError.invalidData
            }
            return image
        }
        
        loadingTasks[url] = task
        
        do {
            let image = try await task.value
            cache[url] = image
            loadingTasks[url] = nil
            return image
        } catch {
            loadingTasks[url] = nil
            throw error
        }
    }
}

🚀 七、高级技巧与最佳实践

7.1 避免数据竞争

1. 优先使用Actor保护共享状态
• 编译器保证数据隔离
• 自动序列化访问
• 避免手动加锁

2. 使用Sendable标记跨并发域的类型
• 值类型优先（struct/enum）
• 避免在闭包中捕获可变状态
• 使用@Sendable闭包

3. 使用@MainActor确保UI更新在主线程
• 标记ViewModel类
• 标记UI更新方法
• 使用MainActor.run

7.2 性能优化

  • 使用async let实现并发执行 - 多个独立异步操作同时执行
  • 合理使用TaskGroup批量处理 - 动态数量的并发任务
  • 避免过度创建Task - Task有创建开销，复用现有Task
  • 使用Actor本地缓存减少异步调用 - 降低await频率
  • 选择合适的Task优先级 - 根据任务重要性设置优先级

7.3 错误处理

  • 使用try/catch统一处理异步错误 - 简化错误处理逻辑
  • 在TaskGroup中处理部分失败 - 不让一个失败影响整体
  • 利用Task取消机制及时释放资源 - 使用withTaskCancellationHandler
  • 使用Result类型封装异步结果 - 延迟错误处理

7.4 调试技巧

Xcode调试工具：
• Task Debugger：查看任务层次结构
• Runtime Issues：检测数据竞争
• Thread Sanitizer：运行时检测线程问题
• Instruments - System Trace：分析并发性能
