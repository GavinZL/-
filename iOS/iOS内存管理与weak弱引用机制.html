一、概念与背景

1.1 内存管理的本质

iOS采用引用计数（Reference Counting）机制管理对象内存。当对象的引用计数为0时，系统自动释放该对象。

核心原则：谁创建谁释放，谁持有谁负责。

1.2 引用类型对比

类型引用计数释放后场景
strong+1保持原值默认，拥有所有权
weak不变自动置nil避免循环引用
unowned不变野指针⚠️确定生命周期
copy新对象+1不受影响不可变对象

1.3 演进历程

  • MRC时代：手动retain/release
  • ARC时代：编译器自动插入内存管理代码（iOS 5+）
  • Swift时代：更安全，编译期检查，值类型优先
📌 注意：ARC是编译期特性，不是垃圾回收！运行时仍是引用计数机制。

二、核心内存管理机制

2.1 引用计数存储位置

2.1.1 isa指针中的extra_rc字段（19位）

// objc4-781源码 objc-private.h
union isa_t {
    Class cls;
    uintptr_t bits;
    struct {
        uintptr_t nonpointer        : 1;  // 优化的isa
        uintptr_t has_assoc         : 1;  // 有关联对象
        uintptr_t has_cxx_dtor      : 1;  // 有C++析构
        uintptr_t shiftcls          : 33; // 类指针(ARM64)
        uintptr_t magic             : 6;  // 魔数
        uintptr_t weakly_referenced : 1;  // 被弱引用
        uintptr_t deallocating      : 1;  // 正在释放
        uintptr_t has_sidetable_rc  : 1;  // RC溢出到SideTable
        uintptr_t extra_rc          : 19; // ⭐额外引用计数(0~524287)
    };
};
优化：extra_rc可存储0~524,287的引用计数，绝大多数对象无需额外内存。

2.1.2 SideTable数据结构

// objc4-781源码 NSObject.mm
struct SideTable {
    spinlock_t slock;           // 自旋锁，线程安全
    RefcountMap refcnts;        // ⭐引用计数表(哈希)
    weak_table_t weak_table;    // ⭐弱引用表
};

// 全局64个SideTable，通过对象地址哈希分散存储
static StripedMap<SideTable> SideTables;
💡 设计亮点：64个SideTable降低锁竞争，提升多线程性能。

2.2 引用计数操作

retain流程

id objc_retain(id obj) {
    if (!obj) return obj;
    if (obj->isTaggedPointer()) return obj;  // Tagged Pointer不需管理
    return obj->retain();
}

inline id objc_object::retain() {
    // 1. 尝试在isa的extra_rc中+1
    isa_t oldisa = LoadExclusive(&isa.bits);
    isa_t newisa = oldisa;
    
    // 2. extra_rc未溢出，直接+1
    if (!newisa.has_sidetable_rc()) {
        newisa.extra_rc++;
        if (StoreExclusive(&isa.bits, oldisa.bits, newisa.bits)) {
            return (id)this;
        }
    }
    
    // 3. extra_rc溢出，转移一半到SideTable
    return rootRetain_overflow(tryRetain);
}

release流程

inline bool objc_object::release() {
    // 1. 尝试在extra_rc中-1
    if (newisa.extra_rc > 0) {
        newisa.extra_rc--;
        return false;  // 不需要dealloc
    }
    
    // 2. extra_rc为0，从SideTable借位或dealloc
    return rootRelease_underflow(performDealloc);
}

三、Autorelease机制

3.1 Autorelease概念

autorelease是一种延迟释放机制，它允许对象在当前作用域结束后，在未来某个时刻自动调用release。这在MRC时代用于解决方法返回值的内存管理问题。

核心思想：对象不立即release，而是注册到AutoreleasePool中，等待pool销毁时统一释放。

3.2 AutoreleasePoolPage数据结构

// objc4-781源码 NSObject.mm
class AutoreleasePoolPage {
    static size_t const SIZE = 4096;  // 4KB页大小
    magic_t const magic;              // 完整性检查
    id *next;                         // ⭐指向下一个可用位置
    pthread_t const thread;           // 所属线程
    AutoreleasePoolPage *const parent; // 父页（双向链表）
    AutoreleasePoolPage *child;        // 子页
    uint32_t const depth;              // 深度
    uint32_t hiwat;                    // high water mark
};
// 每个Page可存储约505个对象指针
💡 设计亮点：每个线程独立的Page栈（TLS），多个Page双向链表连接，4KB页大小内存对齐。

3.3 Autorelease工作原理

// @autoreleasepool编译器转换
@autoreleasepool {
    NSString *str = [NSString stringWithFormat:@"Hello"];
}
// 转换为：
void *context = objc_autoreleasePoolPush();  // push: 插入POOL_BOUNDARY
NSString *str = [NSString stringWithFormat:@"Hello"];
objc_autoreleasePoolPop(context);  // pop: 释放所有对象
// AutoreleasePoolPage::push
static inline void * push() {
    id *dest = autoreleaseFast(POOL_BOUNDARY);  // 插入边界标记
    return dest;  // 返回token
}

// AutoreleasePoolPage::pop
static inline void pop(void *token) {
    AutoreleasePoolPage *page = pageForPointer(token);
    id *stop = (id *)token;
    page->releaseUntil(stop);  // 释放到边界
}

void releaseUntil(id *stop) {
    while (this->next != stop) {
        page->next--;
        id obj = *page->next;
        if (obj == POOL_BOUNDARY) break;
        objc_release(obj);  // ⭐调用release
    }
}

3.4 RunLoop与AutoreleasePool

// 主线程RunLoop自动管理Pool
// kCFRunLoopEntry（进入Loop） → objc_autoreleasePoolPush()
// kCFRunLoopBeforeWaiting（休眠前） → Pop旧pool + Push新pool
// kCFRunLoopExit（退出Loop） → objc_autoreleasePoolPop()
生命周期：App启动→RunLoop创建pool→每次事件循环创建新pool→事件处理完毕pop。

3.5 实际应用

// 场景1：循环中大量临时对象
for (int i = 0; i < 100000; i++) {
    @autoreleasepool {  // ⭐每次循环释放
        NSString *str = [NSString stringWithFormat:@"%d", i];
        UIImage *img = [UIImage imageNamed:@"large.png"];
    }
}

// 场景2：非主线程无RunLoop
dispatch_async(queue, ^{
    @autoreleasepool {  // ⭐必须手动创建
        NSData *data = [NSData dataWithContentsOfURL:url];
    }
});
⚠️ 注意：循环中大量autorelease导致内存峰值，非主线程必须手动管理pool。

四、weak弱引用工作原理

4.1 核心数据结构

weak_table_t 全局弱引用表

// objc4-781源码 objc-weak.h
struct weak_table_t {
    weak_entry_t *weak_entries;  // ⭐弱引用条目数组(哈希表)
    size_t num_entries;          // 条目数量
    uintptr_t mask;              // 哈希掩码
    uintptr_t max_hash_displacement;
};

weak_entry_t 弱引用条目

struct weak_entry_t {
    DisguisedPtr<objc_object> referent;  // ⭐被弱引用的对象
    union {
        struct {
            weak_referrer_t *referrers;  // ⭐动态数组: weak指针地址
            uintptr_t num_refs : 62;     // 引用数量
        };
        struct {
            weak_referrer_t inline_referrers[4];  // ⭐内联数组优化
        };
    };
};
// weak_referrer_t = weak指针的地址
存储优化：≤4个weak引用用内联数组，>4个用动态数组。

4.2 weak注册流程

声明 __weak UIViewController *weakVC = vc; 编译器转换为：

UIViewController *weakVC = nil;
objc_initWeak(&weakVC, vc);

// objc_storeWeak核心实现
id objc_storeWeak(id *location, id newObj) {
    // 1. 如果旧对象存在，从weak_table移除
    weak_unregister_no_lock(&oldTable->weak_table, oldObj, location);
    
    // 2. 注册新的weak指针到weak_table
    newObj = weak_register_no_lock(&newTable->weak_table, newObj, location);
    
    // 3. 在isa中标记对象被弱引用
    newObj->setWeaklyReferenced_nolock();
    
    // 4. 赋值给weak指针
    *location = newObj;
    return newObj;
}

weak_register_no_lock注册细节

id weak_register_no_lock(weak_table_t *weak_table, id referent, 
                          id *referrer, bool crashIfDeallocating) {
    // 1. 检查对象是否正在释放
    if (obj->isDeallocating()) {
        _objc_fatal("Cannot form weak reference");
        return nil;
    }
    
    // 2. 在weak_table中查找或创建weak_entry
    weak_entry_t *entry;
    if ((entry = weak_entry_for_referent(weak_table, referent))) {
        append_referrer(entry, referrer);  // 找到，添加weak指针
    } else {
        weak_entry_t new_entry(referent, referrer);
        weak_grow_maybe(weak_table);  // 必要时扩容
        weak_entry_insert(weak_table, &new_entry);  // 插入新entry
    }
    return referent;
}

4.3 weak清理流程（自动置nil）

对象RC为0
↓
dealloc → clearDeallocating
↓
weak_clear_no_lock
遍历weak指针，置为nil
// objc4-781源码 objc-weak.mm
void weak_clear_no_lock(weak_table_t *weak_table, id referent_id) {
    // 1. 在weak_table中查找对象的weak_entry
    weak_entry_t *entry = weak_entry_for_referent(weak_table, referent);
    if (entry == nil) return;
    
    // 2. 遍历所有weak指针，置为nil
    weak_referrer_t *referrers;
    size_t count;
    if (entry->out_of_line_ness) {
        referrers = entry->referrers;  // 动态数组
        count = entry->num_refs;
    } else {
        referrers = entry->inline_referrers;  // 内联数组
        count = 4;
    }
    
    for (size_t i = 0; i < count; ++i) {
        objc_object **referrer = referrers[i];
        if (referrer) {
            *referrer = nil;  // ⭐置为nil
        }
    }
    
    // 3. 移除entry
    weak_entry_remove(weak_table, entry);
}
自动置nil原理：
  1. weak_entry_t存储对象地址 + weak指针地址数组
  2. dealloc时，通过对象地址找到weak_entry
  3. 遍历数组，将每个weak指针置为nil

4.4 weak vs unowned

特性weakunowned
释放后自动置nil✅野指针⚠️
类型OptionalNon-optional
性能需维护weak_table无开销
场景对象可能先释放确定不会先释放
⚠️ unowned警告：仅在100%确定生命周期时使用，否则崩溃。

五、Swift内存管理

5.1 Swift与Objective-C的差异

Swift同样采用ARC引用计数机制，但在语言层面引入了更多安全特性。

特性Objective-CSwift
默认类型引用类型（NSObject）值类型（Struct/Enum）
引用语法strong/weak/__weakstrong/weak/unowned
编译期检查较弱强类型、Optional检查
内存安全手动管理指针无原始指针，更安全
值类型无（C struct）Struct/Enum一等公民

5.2 值类型 vs 引用类型

// 值类型 - 栈上分配，拷贝传递
struct Point {
    var x: Int
    var y: Int
}
var p1 = Point(x: 10, y: 20)
var p2 = p1  // ⭐拷贝值
p2.x = 30
print(p1.x)  // 10

// 引用类型 - 堆上分配，ARC管理
class Person {
    var name: String
    init(name: String) { self.name = name }
}
var person1 = Person(name: "Alice")  // RC=1
var person2 = person1  // ⭐引用传递，RC=2
person2.name = "Bob"
print(person1.name)  // "Bob"
设计理念：值类型优先，避免不必要的引用计数，Array/Dictionary/String都是值类型。

5.3 Swift闭包捕莞列表

class NetworkManager {
    var onComplete: (() -> Void)?
    
    // ❗️ 错误：循环引用
    func fetch1() {
        onComplete = {
            print(self.url)  // self持有onComplete
        }
    }
    
    // ✅ weak捕莞
    func fetch2() {
        onComplete = { [weak self] in
            guard let self = self else { return }
            print(self.url)
        }
    }
    
    // ✅ unowned捕莞
    func fetch3() {
        onComplete = { [unowned self] in
            print(self.url)
        }
    }
}

5.4 Copy-on-Write (COW)

// Swift值类型的COW优化
var array1 = [1, 2, 3]
var array2 = array1  // ⭐不拷贝，共享内存
array2.append(4)  // ⭐此时才拷贝
print(array1)  // [1, 2, 3]
print(array2)  // [1, 2, 3, 4]

5.5 defer语句

func processFile() throws {
    let file = openFile("data.txt")
    defer {  // ⭐作用域结束时执行
        closeFile(file)
    }
    if someCondition {
        throw SomeError()  // defer仍执行
    }
}

5.6 Swift最佳实践

// 1. 优先使用值类型
struct User {  // ✅ 值类型
    let id: Int
    let name: String
}

// 2. 闭包明确捕莞
fetchData { [weak self] in
    guard let self = self else { return }
    self.handleResult()
}

// 3. defer确保资源释放
func process() {
    let resource = acquire()
    defer { release(resource) }
}
💡 优化总结：值类型优先、COW优化、编译期检查、明确捕莹、defer语句。

六、实际应用场景

6.1 Delegate模式

// ✅ 正确示例
protocol NetworkDelegate: AnyObject {
    func didReceiveData(_ data: Data)
}

class NetworkManager {
    weak var delegate: NetworkDelegate?  // ⭐weak避免循环引用
}

class ViewController: UIViewController, NetworkDelegate {
    let manager = NetworkManager()
    
    override func viewDidLoad() {
        super.viewDidLoad()
        manager.delegate = self  // 不会循环引用
    }
}

6.2 闭包循环引用

// ❌ 错误：闭包捕获self
class ViewController {
    var onComplete: (() -> Void)?
    func setup() {
        onComplete = {
            print(self.name)  // self持有闭包，闭包捕获self → 循环引用
        }
    }
}

// ✅ 正确：weak self
func setup() {
    onComplete = { [weak self] in
        guard let self = self else { return }
        print(self.name)
    }
}

6.3 NSTimer循环引用

// ❌ 错误：Timer强引用VC
self.timer = [NSTimer scheduledTimerWithTimeInterval:1.0
                                              target:self
                                            selector:@selector(timerFired)
                                            userInfo:nil
                                             repeats:YES];

// ✅ 解决方案1：iOS 10+ block API
self.timer = [NSTimer scheduledTimerWithTimeInterval:1.0 repeats:YES block:^{
    __weak typeof(self) weakSelf = self;
    [weakSelf timerFired];
}];

// ✅ 解决方案2：使用NSProxy中间对象
self.timer = [NSTimer scheduledTimerWithTimeInterval:1.0
                                              target:[WeakProxy proxyWithTarget:self]
                                            selector:@selector(timerFired)
                                            userInfo:nil
                                             repeats:YES];

7.2 性能优化建议

避免不必要的weak

// ❌ 不必要的weak（闭包不会被持有）
DispatchQueue.global().async { [weak self] in
    // 这个闭包不会被self持有，无需weak
}

// ✅ 正确：闭包被self持有时才用weak
self.handler = { [weak self] in
    self?.doSomething()  // handler是self的属性，需要weak
}

weak vs unowned选择

// unowned适用场景：闭包生命周期 < 对象生命周期
UIView.animate(withDuration: 1.0) { [unowned self] in
    self.view.alpha = 0.5  // 动画block一定先于VC释放
}

// weak适用场景：不确定生命周期
networkManager.fetchData { [weak self] data in
    self?.updateUI(data)  // 网络回调可能在VC释放后
}
