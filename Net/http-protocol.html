    🎯 第一层：概念与背景

    1.1 HTTP发展历史

    📌 发展时间线
    • 1991年：HTTP/0.9 - Tim Berners-Lee发明，仅支持GET
    • 1996年：HTTP/1.0 - RFC 1945，引入Header和POST
    • 1997年：HTTP/1.1 - RFC 2068，持久连接、管道化
    • 2015年：HTTP/2 - RFC 7540，二进制分帧、多路复用
    • 2022年：HTTP/3 - RFC 9114，基于QUIC的传输

    1.2 版本演进对比

    版本 传输协议 连接 性能 核心特性
    HTTP/0.9 TCP 短连接 低 仅GET，无Header
    HTTP/1.0 TCP 短连接 低 Header，状态码，POST
    HTTP/1.1 TCP 长连接 中 Keep-Alive，管道化，分块传输
    HTTP/2 TCP 多路复用 高 二进制分帧，服务器推送，头部压缩
    HTTP/3 QUIC/UDP 0-RTT 极高 无队头阻塞，快速握手，连接迁移

    1.4 URL与URI详解

    /* URL结构 */
https://user:pass@www.example.com:443/path/to/resource?key=value#fragment
|____| |________| |________________| |_| |________________| |_______| |______|
  |        |              |           |          |              |        |
scheme  userinfo        host        port       path          query   fragment

/* 组成部分 */
- scheme:   协议（http, https, ftp等）
- userinfo: 用户信息（很少使用）
- host:     主机名或IP
- port:     端口（默认80/443）
- path:     资源路径
- query:    查询参数
- fragment: 锚点（不发送到服务器）

/* URI vs URL vs URN */
URI (Uniform Resource Identifier)     // 统一资源标识符
 ├─ URL (Uniform Resource Locator)    // 定位资源的地址
 └─ URN (Uniform Resource Name)       // 资源的名称

/* 示例 */
URL: https://www.example.com/book/123
URN: urn:isbn:0-486-27557-4

    2.2 HTTP状态码

    2.2.1 状态码分类

    分类 范围 含义
    1xx 信息性 请求已接收，继续处理
    2xx 成功 请求成功处理
    3xx 重定向 需要进一步操作
    4xx 客户端错误 请求有语法错误或无法实现
    5xx 服务器错误 服务器未能实现合法请求

    2.2.2 常见状态码详解

    /* 2xx - 成功 */
200 OK                   // 请求成功
201 Created              // 资源已创建
202 Accepted             // 已接受，但未处理完成
204 No Content           // 成功但无返回内容
206 Partial Content      // 部分内容（范围请求）

/* 3xx - 重定向 */
301 Moved Permanently    // 永久重定向
302 Found                // 临时重定向
303 See Other            // 使用GET查看其他位置
304 Not Modified         // 资源未修改（缓存）
307 Temporary Redirect   // 临时重定向，保持方法
308 Permanent Redirect   // 永久重定向，保持方法

/* 4xx - 客户端错误 */
400 Bad Request          // 请求语法错误
401 Unauthorized         // 需要身份验证
403 Forbidden            // 拒绝访问
404 Not Found            // 资源不存在
405 Method Not Allowed   // 方法不允许
408 Request Timeout      // 请求超时
409 Conflict             // 资源冲突
413 Payload Too Large    // 请求实体过大
414 URI Too Long         // URI过长
429 Too Many Requests    // 请求过多（限流）

/* 5xx - 服务器错误 */
500 Internal Server Error   // 服务器内部错误
501 Not Implemented         // 不支持该功能
502 Bad Gateway             // 网关错误
503 Service Unavailable     // 服务不可用
504 Gateway Timeout         // 网关超时

    2.3.2 重要Header详解

    /* Host（HTTP/1.1必需） */
Host: www.example.com:8080
// 用途：虚拟主机，一个IP多个域名

/* Content-Type（指定内容类型） */
Content-Type: text/html; charset=utf-8
Content-Type: application/json
Content-Type: multipart/form-data; boundary=----WebKitFormBoundary
Content-Type: application/x-www-form-urlencoded

/* Accept系列（内容协商） */
Accept: application/json, text/html;q=0.9, */*;q=0.8
Accept-Encoding: gzip, deflate, br
Accept-Language: zh-CN,zh;q=0.9,en;q=0.8
// q值：质量因子，范围0-1

/* Range（范围请求） */
Range: bytes=0-1023           // 请求前1KB
Range: bytes=1024-2047        // 请求第2KB
Range: bytes=-500             // 请求最后500字节
Range: bytes=0-499, 1000-1499 // 请求多个范围

/* Content-Range（范围响应） */
Content-Range: bytes 0-1023/5000
// 格式：bytes 起始-结束/总大小

/* Transfer-Encoding（传输编码） */
Transfer-Encoding: chunked
// 分块传输，不需要Content-Length

/* Connection（连接管理） */
Connection: keep-alive        // HTTP/1.1默认
Connection: close             // 关闭连接
Connection: Upgrade           // 协议升级

    2.4 Cookie与Session机制

    2.4.1 Cookie机制

    /* Cookie工作流程 */

// 1. 服务器设置Cookie
HTTP/1.1 200 OK
Set-Cookie: sessionId=abc123; Path=/; HttpOnly; Secure
Set-Cookie: theme=dark; Max-Age=86400; SameSite=Strict

// 2. 浏览器后续请求自动携带
GET /profile HTTP/1.1
Host: www.example.com
Cookie: sessionId=abc123; theme=dark

/* Cookie属性详解 */
Set-Cookie: name=value; // 必需
            Domain=example.com;       // 域名范围
            Path=/;                   // 路径范围
            Expires=Wed, 21 Dec 2024; // 过期时间（绝对）
            Max-Age=3600;              // 过期时间（相对，秒）
            Secure;                   // 仅HTTPS传输
            HttpOnly;                 // 禁止JS访问
            SameSite=Strict           // CSRF防护

/* SameSite属性 */
SameSite=Strict    // 完全禁止跨站发送
SameSite=Lax       // 导航跨站允许（默认）
SameSite=None      // 允许跨站（需配合Secure）

    2.4.2 Session机制

    /* Session实现方式 */

// 方式1：基于Cookie存储Session ID
Client                    Server
  |                          |
  | 1. POST /login           |
  | -----------------------> | 创建Session，生成ID
  |                          | sessions["abc123"] = {user: "john"}
  | 2. Set-Cookie: sid=abc123|
  | <----------------------- |
  |                          |
  | 3. GET /profile          |
  |    Cookie: sid=abc123    |
  | -----------------------> | 从sessions["abc123"]获取数据
  |                          |

// 方式2：URL重写（Cookie被禁用时）
GET /profile;jsessionid=ABC123 HTTP/1.1

/* 服务端Session存储 */
#include <map>
#include <string>

// 简单Session实现
struct SessionData {
    std::string user_id;
    time_t created_at;
    time_t last_access;
    std::map<std::string, std::string> data;
};

class SessionManager {
private:
    std::map<std::string, SessionData> sessions;
    
public:
    std::string create_session(const std::string& user_id) {
        std::string sid = generate_random_id();
        SessionData data;
        data.user_id = user_id;
        data.created_at = time(NULL);
        data.last_access = time(NULL);
        sessions[sid] = data;
        return sid;
    }
    
    SessionData* get_session(const std::string& sid) {
        auto it = sessions.find(sid);
        if (it != sessions.end()) {
            it->second.last_access = time(NULL);
            return &it->second;
        }
        return nullptr;
    }
    
    void destroy_session(const std::string& sid) {
        sessions.erase(sid);
    }
    
    void cleanup_expired(int timeout_seconds) {
        time_t now = time(NULL);
        for (auto it = sessions.begin(); it != sessions.end();) {
            if (now - it->second.last_access > timeout_seconds) {
                it = sessions.erase(it);
            } else {
                ++it;
            }
        }
    }
};
    ⚠️ Cookie vs Session
    • Cookie：存储在客户端，大小限制4KB，安全性较低
    • Session：存储在服务端，无大小限制，安全性高
    • 典型组合：Cookie存Session ID，Session存用户数据

    2.5 HTTP缓存机制

    2.5.1 缓存策略

    /* 缓存类型 */

// 1. 强缓存（不发请求，直接使用缓存）
Cache-Control: max-age=3600          // 缓存1小时（优先）
Expires: Thu, 21 Dec 2023 12:00:00 GMT  // 过期时间（HTTP/1.0）

// 2. 协商缓存（发请求验证，304则使用缓存）
// 方式A：Last-Modified / If-Modified-Since
HTTP/1.1 200 OK
Last-Modified: Wed, 20 Dec 2023 10:00:00 GMT

GET /style.css HTTP/1.1
If-Modified-Since: Wed, 20 Dec 2023 10:00:00 GMT

HTTP/1.1 304 Not Modified  // 未修改，使用缓存

// 方式B：ETag / If-None-Match（更精确）
HTTP/1.1 200 OK
ETag: "686897696a7c876b7e"

GET /style.css HTTP/1.1
If-None-Match: "686897696a7c876b7e"

HTTP/1.1 304 Not Modified

    2.5.2 Cache-Control指令

    指令 作用 使用场景
    max-age 缓存最大时间（秒） 静态资源
    no-cache 需要验证后才能使用 频繁更新的资源
    no-store 完全禁止缓存 敏感信息
    public 可被任何缓存存储 公共资源
    private 仅浏览器缓存 用户私有数据
    must-revalidate 过期必须验证 重要资源
    immutable 永不改变 带版本号的资源

    2.5.3 缓存决策流程

    /* 浏览器缓存决策 */

请求资源
   |
   v
是否有缓存？
   |           |
  否          是
   |           |
   |           v
   |     检查Cache-Control/Expires
   |           |
   |      是否过期？
   |      |        |
   |     否       是
   |      |        |
   |   使用缓存    v
   |           是否有ETag/Last-Modified？
   |                |              |
   |               是             否
   |                |              |
   v                v              v
发送请求      发送条件请求      发送请求
   |                |              |
   v                v              v

/* 最佳实践 */

// 1年缓存，永不改变

// HTML文件
Cache-Control: no-cache
// 每次验证

// API响应

// 私有数据，每次验证

// 敏感信息
Cache-Control: no-store, no-cache, must-revalidate
// 完全不缓存

    2.6 HTTP连接管理

    2.6.1 短连接 vs 长连接

    /* HTTP/1.0 - 短连接 */
Client                    Server
  |                          |
  | TCP 3次握手              |
  | <-------------------->   |
  | GET /1.html              |
  | -----------------------> |
  | 200 OK                   |
  | <----------------------- |
  | TCP 4次挥手              |
  | <-------------------->   |
  |                          |
  | TCP 3次握手（新连接）     |
  | <-------------------->   |
  | GET /2.html              |
  | -----------------------> |
  // 每个资源都需要新建连接

/* HTTP/1.1 - 长连接（Keep-Alive）*/
Client                    Server
  |                          |
  | TCP 3次握手              |
  | <-------------------->   |
  | GET /1.html              |
  |   Connection: keep-alive |
  | -----------------------> |
  | 200 OK                   |
  | <----------------------- |
  |                          |
  | GET /2.html（复用连接）   |
  | -----------------------> |
  | 200 OK                   |
  | <----------------------- |
  |                          |
  | GET /3.html              |
  | -----------------------> |
  // 一个TCP连接复用多次

/* Keep-Alive参数 */
Connection: keep-alive
Keep-Alive: timeout=5, max=100
// timeout: 空闲超时时间（秒）
// max: 最大请求数

    2.6.2 HTTP管道化（Pipelining）

    /* HTTP/1.1管道化（默认禁用）*/

// 非管道化：请求-响应-请求-响应
Client: REQ1 -------> Server
Client: <------- RES1 Server
Client: REQ2 -------> Server
Client: <------- RES2 Server

// 管道化：批量请求-批量响应
Client: REQ1 -------> Server
Client: REQ2 -------> Server  // 不等RES1就发送
Client: REQ3 -------> Server
Client: <------- RES1 Server
Client: <------- RES2 Server
Client: <------- RES3 Server

/* 管道化的问题 */
// 1. 队头阻塞（Head-of-Line Blocking）
//    如果RES1处理慢，RES2/RES3都要等待
// 2. 服务器必须按顺序响应
// 3. 幂等请求才安全（GET/HEAD）

    2.6.3 HTTP/2多路复用

    /* HTTP/2解决队头阻塞 */

// 二进制分帧
HTTP/1.1: GET /index.html\r\n...  // 文本协议
HTTP/2:   [Frame Header][Frame Payload]  // 二进制帧

// 多路复用（一个TCP连接，多个流）
         TCP Connection
┌───────────────────────────┐
│  Stream 1: /index.html    │
│  Stream 3: /style.css     │
│  Stream 5: /script.js     │
│  Stream 7: /image.png     │
└───────────────────────────┘

// 流的特点
// - 每个流独立
// - 可并发传输
// - 流之间不阻塞
// - 流有优先级

/* 帧类型 */
DATA          // 数据帧
HEADERS       // 头部帧
PRIORITY      // 优先级帧
RST_STREAM    // 流终止帧
SETTINGS      // 设置帧
PUSH_PROMISE  // 服务器推送帧
PING          // 心跳帧
GOAWAY        // 连接终止帧
WINDOW_UPDATE // 流量控制帧

/* C++ libcurl上传示例 */
#include <curl/curl.h>

void upload_file(const char* filepath) {
    CURL *curl = curl_easy_init();
    
    if (curl) {
        struct curl_httppost *formpost = NULL;
        struct curl_httppost *lastptr = NULL;
        
        // 添加表单字段
        curl_formadd(&formpost, &lastptr,
                     CURLFORM_COPYNAME, "username",
                     CURLFORM_COPYCONTENTS, "john",
                     CURLFORM_END);
        
        // 添加文件
        curl_formadd(&formpost, &lastptr,
                     CURLFORM_COPYNAME, "file",
                     CURLFORM_FILE, filepath,
                     CURLFORM_END);
        
        curl_easy_setopt(curl, CURLOPT_URL, "http://example.com/upload");
        curl_easy_setopt(curl, CURLOPT_HTTPPOST, formpost);
        
        CURLcode res = curl_easy_perform(curl);
        
        curl_formfree(formpost);
        curl_easy_cleanup(curl);
    }
}

    3.4.1 Nginx反向代理配置

    # nginx.conf

http {
    # 上游服务器组
    upstream backend {
        server 192.168.1.10:8080 weight=3;  # 权重3
        server 192.168.1.11:8080 weight=2;
        server 192.168.1.12:8080 backup;     # 备用
        
        keepalive 32;  # 保持32个长连接
    }
    
    server {
        listen 80;
        server_name example.com;
        
        location / {
            proxy_pass http://backend;
            
            # 代理Header
            proxy_set_header Host $host;
            proxy_set_header X-Real-IP $remote_addr;
            proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
            proxy_set_header X-Forwarded-Proto $scheme;
            
            # 超时设置
            proxy_connect_timeout 60s;
            proxy_send_timeout 60s;
            proxy_read_timeout 60s;
            
            # 缓存
            proxy_buffering on;
            proxy_buffer_size 4k;
            proxy_buffers 8 4k;
        }
    }
}

    /* Server Push原理 */

Client                                 Server
  |                                       |
  | GET /index.html                       |
  | ------------------------------------> |
  |                                       |
  | PUSH_PROMISE stream_id=2            |
  |   :path: /style.css                  |
  | <------------------------------------ | // 服务器承诺推送
  |                                       |
  | HEADERS + DATA stream_id=1         |
  |   (index.html content)               |

  |   (style.css content)                |
  | <------------------------------------ | // 推送CSS

    4.4 HTTP/3与QUIC

    4.4.1 HTTP/3优势

    /* HTTP/3 vs HTTP/2 */

// HTTP/2的问题：TCP队头阻塞
TCP Layer:  [Packet 1] [Packet 2 Lost] [Packet 3] [Packet 4]
                                   ↓
                            等待重传↓
                                   ↓
HTTP/2:     Stream 1   Stream 2   Stream 3   Stream 4
            阻塞     阻塞     阻塞     阻塞

// HTTP/3：基于UDP，流独立
UDP Layer:  [Packet 1] [Packet 2 Lost] [Packet 3] [Packet 4]
                                   ↓
QUIC:       Stream 1   Stream 2   Stream 3   Stream 4
            ✓        重传     ✓        ✓
                     （不影响其他流）

/* QUIC特性 */
1. 0-RTT建立连接
   // TCP+TLS: 3 RTT
   // QUIC: 0-1 RTT

2. 连接迁移
   // 使用Connection ID，不IP/端口
   // Wi-Fi -> 4G切换不断开

3. 内置加密
   // TLS 1.3集成

4. 改进的拥塞控制
   // BBR算法

    4.4.2 QUIC框架结构

    /* QUIC协议堆栈 */

+---------------------------+
|      HTTP/3 (RFC 9114)    |  // 应用层
+---------------------------+
|      QPACK (RFC 9204)     |  // 头部压缩
+---------------------------+
|       QUIC (RFC 9000)     |  // 传输层
|  - 连接管理               |
|  - 流管理                 |
|  - 可靠传输               |
|  - 拥塞控制               |
+---------------------------+
|       TLS 1.3             |  // 加密层
+---------------------------+
|          UDP              |  // 网络层
+---------------------------+

/* QUIC包结构 */
+-+-+-+-+-+-+-+-+
|1|1|T T|R R|P P|  // Header Form
+-+-+-+-+-+-+-+-+
|Version (32)   |  // QUIC版本
+-+-+-+-+-+-+-+-+
|DCID Len (8)  |  // 目标连接ID长度
+-+-+-+-+-+-+-+-+
|Destination  |  // 目标连接ID
|Connection ID|
