    🎯 第一层：概念与背景

    1.1 多线程内存模型的诞生背景

    在C++11之前，C++标准未定义多线程行为，程序员依赖平台特定的API（如pthread、Windows线程）。这导致：

    • 可移植性差：不同平台有不同的内存模型
    • 编译器优化受限：编译器不知道哪些变量需要同步
    • 错误难以调试：内存可见性问题在不同硬件上表现不同
    📌 历史演进
    • 1979年: Lamport提出顺序一致性（Sequential Consistency）
    • 1990年: 弱内存模型（Weak Memory Model）理论发展
    • 2008年: Hans Boehm等人推动C++内存模型标准化
    • 2011年: C++11引入完整的内存模型和atomic库
    • 2020年: C++20增强atomic功能（wait/notify机制）

    1.2 内存重排序问题

    内存重排序发生在两个层面：

    1.2.1 编译器重排序

    // 原始代码
int a = 0, b = 0;
void thread1() {
    a = 1;  // 语句1
    b = 1;  // 语句2
}

// 编译器可能优化为：
void thread1() {
    b = 1;  // 先执行语句2
    a = 1;  // 后执行语句1
}

    1.2.2 CPU重排序

    即使编译器没有重排，CPU也会在运行时重排序指令以提升性能：

    重排序类型 描述 x86-64 ARM/POWER
    Store-Store 后面的写操作可能先于前面的写操作可见 ❌ ✅
    Load-Load 后面的读操作可能先于前面的读操作执行 ❌ ✅
    Load-Store 后面的写操作可能先于前面的读操作 ✅ ✅
    Store-Load 后面的读操作可能先于前面的写操作 ✅ ✅
    ⚠️ 经典问题：Dekker算法失效 在没有内存序保证的情况下，经典的Dekker互斥算法在现代CPU上会失效。

    1.3 顺序一致性 vs 宽松内存模型

    1.3.1 顺序一致性（Sequential Consistency - SC）

    Lamport定义：程序的执行结果等同于所有线程的操作按某种全局顺序交错执行。

    1.3.2 宽松内存模型的必要性

    方面 顺序一致性 宽松内存模型
    正确性 易于理解和验证 需要深入理解内存序
    性能 需要大量内存屏障，性能低 可根据需求选择最小同步
    硬件支持 x86较好，ARM/POWER代价高 充分利用硬件特性

    1.4 happens-before关系

    C++内存模型的核心概念，定义操作之间的可见性保证。

    1.4.1 定义

    如果操作A happens-before 操作B，则：

    • A的结果对B可见
    • A在B之前执行（从程序语义角度）

    1.5 内存序的分类与层次

    内存序 类别 同步保证 性能 使用场景
    memory_order_relaxed 宽松 仅原子性，无同步 最快 计数器
    memory_order_consume 获取 数据依赖排序 快 已废弃
    memory_order_acquire 获取 acquire语义 中等 读锁、读屏障
    memory_order_release 释放 release语义 中等 写锁、写屏障
    memory_order_acq_rel 获取-释放 两者结合 较慢 RMW操作
    memory_order_seq_cst 顺序一致 全局顺序 最慢 默认，简单场景
    💡 选择原则
    • 默认使用 seq_cst，除非有性能瓶颈
    • 只需要原子性：使用 relaxed
    • 需要同步：使用 acquire/release
    • 需要全局顺序：使用 seq_cst

    ⚙️ 第二层：核心机制与实现原理

    2.1 六种内存序详解

    2.1.1 memory_order_relaxed（宽松序）

    特性：仅保证操作的原子性，不提供任何同步或排序保证。

    // 示例：计数器（不需要同步）
std::atomic<int> counter{0};

void increment() {
    counter.fetch_add(1, std::memory_order_relaxed);
}

int get_count() {
    return counter.load(std::memory_order_relaxed);
}

    2.1.2 memory_order_acquire（获取序）

    特性：load操作，防止后续读写操作重排到此操作之前。

    // acquire语义
std::atomic<bool> flag{false};
int data = 0;

// Thread 2（消费者）
while (!flag.load(std::memory_order_acquire)) {
    // 自旋等待
}
// 这里保证能看到Thread 1对data的修改
assert(data == 42);

    内存屏障：

    • x86-64: 无需额外指令（TSO模型天然满足）
    • ARM64: ldar（Load-Acquire）
    • POWER: isync

    2.1.3 memory_order_release（释放序）

    特性：store操作，防止前面的读写操作重排到此操作之后。

    // release语义
std::atomic<bool> flag{false};
int data = 0;

// Thread 1（生产者）
data = 42;
flag.store(true, std::memory_order_release);
// release保证data的修改在flag之前完成

    内存屏障：

    • x86-64: 无需额外指令
    • ARM64: stlr（Store-Release）
    • POWER: lwsync

    2.1.4 memory_order_acq_rel（获取-释放序）

    特性：同时具有acquire和release语义，用于RMW（Read-Modify-Write）操作。

    // 示例：自旋锁
class SpinLock {
    std::atomic<bool> flag{false};
public:
    void lock() {
        while (flag.exchange(true, std::memory_order_acq_rel)) {
            // 自旋
        }
    }
    
    void unlock() {
        flag.store(false, std::memory_order_release);
    }
};

    2.1.5 memory_order_seq_cst（顺序一致性）

    特性：最强的内存序，保证全局的单一总顺序。

    // 经典示例：Dekker算法修正版
std::atomic<bool> x{false}, y{false};
std::atomic<int> z{0};

// Thread 1
x.store(true, std::memory_order_seq_cst);
if (!y.load(std::memory_order_seq_cst)) {
    ++z;
}

// Thread 2
y.store(true, std::memory_order_seq_cst);
if (!x.load(std::memory_order_seq_cst)) {
    ++z;
}

// 保证：z最终值为0或1，不会是2

    实现代价：

    • x86-64: store需要 mfence 或 lock xchg
    • ARM64: 需要完整的 dmb 屏障
    • POWER: 需要 sync 指令

    2.1.6 memory_order_consume（消费序）

    🚫 已废弃

    C++17标准将consume标记为不鼓励使用，所有主流编译器将其实现为acquire。原因：

    • 编译器难以正确实现数据依赖跟踪
    • 性能提升不明显
    • 容易导致微妙的bug

    2.2 编译器重排序机制

    编译器 屏障指令 作用
    GCC/Clang asm volatile("" ::: "memory") 阻止编译器重排序
    MSVC _ReadWriteBarrier() 阻止编译器重排序
    C++11 atomic_signal_fence() 编译器屏障

    2.3 CPU重排序与内存屏障

    2.3.1 x86-64内存模型（TSO）

    x86-64采用较强的TSO模型，特点：

    • ✅ Store-Store不重排
    • ✅ Load-Load不重排
    • ✅ Load-Store不重排
    • ❌ Store-Load可能重排（Store Buffer导致）
    // x86-64内存屏障指令
asm volatile("mfence");  // 全屏障
asm volatile("sfence");  // Store屏障
asm volatile("lfence");  // Load屏障

// seq_cst store在x86上的实现
// 方式1: MFENCE + MOV
void store_seq_cst(std::atomic<int>* p, int val) {
    asm volatile("mfence");
    p->store(val, std::memory_order_relaxed);
}

// 方式2: LOCK XCHG (更快)
void store_seq_cst_fast(std::atomic<int>* p, int val) {
    int dummy;
    asm volatile(
        "lock xchg %0, %1"
        : "=r"(dummy), "=m"(*p)
        : "0"(val)
    );
}
    📌 x86-64的Store Buffer

    x86-64 CPU使用Store Buffer来提升性能：

    • 写操作先进入Store Buffer，异步刷新到缓存
    • 导致Store-Load重排序（后续读操作可能绕过Store Buffer）
    • MFENCE刷新Store Buffer，保证全局可见性

    2.3.2 ARM64内存模型（弱内存模型）

    ARM64允许更激进的重排序，需要显式屏障：

    // ARM64屏障指令
DMB ISH       // Data Memory Barrier (Inner Shareable)
DMB ISHST     // Store屏障
DMB ISHLD     // Load屏障
DSB ISH       // 更强的屏障（等待所有访问完成）

// ARM64 Load-Acquire / Store-Release
LDAR X0, [X1]  // Load-Acquire
STLR X0, [X1]  // Store-Release

// C++代码对应的ARM64汇编
// std::atomic x;
// x.load(memory_order_acquire)
LDAR W0, [X0]  // 单条指令实现acquire

// x.store(42, memory_order_release)
MOV W1, #42
STLR W1, [X0]  // 单条指令实现release

// x.store(42, memory_order_seq_cst)
MOV W1, #42
STLR W1, [X0]
DMB ISH        // 需要额外屏障保证全局顺序

    2.3.3 POWER内存模型（最弱）

    POWER架构允许几乎所有形式的重排序：

    // POWER屏障指令
sync       // 全屏障（最强，等待所有操作完成）
lwsync     // Light-weight sync（不阻止Store-Load重排）
isync      // Instruction sync（acquire语义）
eieio      // 设备I/O屏障

// acquire实现（POWER）
ld r3, 0(r4)   // load
cmpw r3, r3    // 创建数据依赖
bne- $+4       // 永不跳转的分支
isync          // 指令同步屏障

// release实现（POWER）
lwsync         // 轻量级同步
std r3, 0(r4)  // store

    2.4 libc++/libstdc++的实现分析

    2.4.1 libc++ atomic实现（Clang）

    // libc++/include/atomic (简化版)
template<typename T>
struct atomic {
    using value_type = T;
    
    void store(T desired, memory_order order = memory_order_seq_cst) noexcept {
        __atomic_store(&_value, &desired, __to_gcc_order(order));
    }
    
    T load(memory_order order = memory_order_seq_cst) const noexcept {
        T result;
        __atomic_load(&_value, &result, __to_gcc_order(order));
        return result;
    }
    
    T exchange(T desired, memory_order order = memory_order_seq_cst) noexcept {
        T result;
        __atomic_exchange(&_value, &desired, &result, __to_gcc_order(order));
        return result;
    }
    
    bool compare_exchange_weak(T& expected, T desired,
                               memory_order success,
                               memory_order failure) noexcept {
        return __atomic_compare_exchange(&_value, &expected, &desired,
                                            true,
                                            __to_gcc_order(success),
                                            __to_gcc_order(failure));
    }
    
private:
    T _value;
};

// 内存序转换
static constexpr int __to_gcc_order(memory_order order) {
    switch (order) {
        case memory_order_relaxed: return __ATOMIC_RELAXED;
        case memory_order_acquire: return __ATOMIC_ACQUIRE;
        case memory_order_release: return __ATOMIC_RELEASE;
        case memory_order_acq_rel: return __ATOMIC_ACQ_REL;
        case memory_order_seq_cst: return __ATOMIC_SEQ_CST;
    }
}

    2.4.2 编译器内置函数

    GCC/Clang提供的内置原子操作：

    // __atomic builtins (C++11标准映射)
__atomic_load_n(&var, __ATOMIC_ACQUIRE);
__atomic_store_n(&var, value, __ATOMIC_RELEASE);
__atomic_exchange_n(&var, value, __ATOMIC_ACQ_REL);
__atomic_compare_exchange_n(&var, &expected, desired, 
                            false, __ATOMIC_ACQ_REL, __ATOMIC_ACQUIRE);
__atomic_fetch_add(&var, 1, __ATOMIC_RELAXED);

// 线程栅栏
__atomic_thread_fence(__ATOMIC_SEQ_CST);
__atomic_signal_fence(__ATOMIC_SEQ_CST);  // 仅编译器屏障

// GCC旧版本__sync builtins (不推荐)
__sync_fetch_and_add(&var, 1);  // 等价于seq_cst
__sync_bool_compare_and_swap(&var, old, new);

    2.5 内核atomic实现

    2.5.1 Linux内核的atomic_t（x86-64）

    // arch/x86/include/asm/atomic.h (简化)
typedef struct {
    int counter;
} atomic_t;

static inline void atomic_add(int i, atomic_t *v) {
    asm volatile(LOCK_PREFIX "addl %1,%0"
                     : "+m" (v->counter)
                     : "ir" (i));
}

static inline int atomic_read(const atomic_t *v) {
    return READ_ONCE(v->counter);  // 防止编译器优化
}

static inline void atomic_set(atomic_t *v, int i) {
    WRITE_ONCE(v->counter, i);
}

// READ_ONCE/WRITE_ONCE定义
#define READ_ONCE(x) \
    ({ \
        typeof(x) __val; \
        __asm__ volatile("" : "=r" (__val) : "0" (x)); \
        __val; \
    })

#define WRITE_ONCE(x, val) \
    ({ \
        typeof(x) __val = (val); \
        __asm__ volatile("" : "=m" (x) : "r" (__val)); \
    })

    2.5.2 内核内存屏障

    // include/asm-generic/barrier.h
#define mb()    asm volatile("mfence" ::: "memory")  // 全屏障
#define rmb()   asm volatile("lfence" ::: "memory")  // 读屏障
#define wmb()   asm volatile("sfence" ::: "memory")  // 写屏障

// SMP条件屏障（x86-64的TSO模型较强，编译器屏障即可）
#define smp_mb()    barrier()
#define smp_rmb()   barrier()
#define smp_wmb()   barrier()
#define barrier()   asm volatile("" ::: "memory")

// acquire/release语义
#define smp_load_acquire(p) \
    ({ \
        typeof(*p) ___p1 = READ_ONCE(*p); \
        barrier(); \
        ___p1; \
    })

#define smp_store_release(p, v) \
    ({ \
        barrier(); \
        WRITE_ONCE(*p, v); \
    })

// RCU相关屏障
#define rcu_dereference(p) \
    ({ \
        typeof(p) _p1 = READ_ONCE(p); \
        smp_read_barrier_depends(); \
        _p1; \
    })
    💡 为什么Linux内核需要这么多屏障？
    • 多架构支持：x86强模型，ARM/POWER弱模型
    • 性能优化：根据具体场景选择最小开销的屏障
    • RCU优化：利用数据依赖避免完整屏障（consume语义）

    3.1 自旋锁实现

    3.1.1 基础版本（TAS锁）

    // Test-And-Set自旋锁
class SpinLock {
    std::atomic<bool> locked{false};
    
public:
    void lock() {
        while (locked.exchange(true, std::memory_order_acquire)) {
            // 自旋等待
        }
    }
    
    void unlock() {
        locked.store(false, std::memory_order_release);
    }
};
    ⚠️ 问题：缓存颠簸（Cache Thrashing）

    TAS锁的问题：每次自旋都会执行exchange，导致：

    • 大量的MESI协议消息（缓存一致性协议）
    • 总线占用率高
    • 性能下降明显

    3.1.2 优化版本（TTAS锁 + 指数退避）

    // Test-Test-And-Set + Exponential Backoff
class OptimizedSpinLock {
    std::atomic<bool> locked{false};
    
public:
    void lock() {
        int spin_count = 0;
        constexpr int MAX_SPINS = 1000;
        
        while (true) {
            // 先用relaxed测试，减少缓存一致性流量
            if (!locked.load(std::memory_order_relaxed) &&
                !locked.exchange(true, std::memory_order_acquire)) {
                return;
            }
            
            // 指数退避：减少竞争
            if (spin_count < MAX_SPINS) {
                for (int i = 0; i < (1 << spin_count); ++i) {
                    __builtin_ia32_pause();  // x86 PAUSE指令
                }
                ++spin_count;
            } else {
                std::this_thread::yield();  // 让出CPU
            }
        }
    }
    
    void unlock() {
        locked.store(false, std::memory_order_release);
    }
};
    💡 PAUSE指令的作用
    • 降低功耗：减少自旋等待时的能量消耗
    • 提高性能：给Store Buffer更多时间刻新数据
    • 避免管道混乱：防止内存顺序违反检测

    3.1.3 Ticket锁（公平锁）

    // Linux内核风格的Ticket Spinlock
class TicketLock {
    std::atomic<uint32_t> ticket{0};
    std::atomic<uint32_t> serving{0};
    
public:
    void lock() {
        uint32_t my_ticket = ticket.fetch_add(1, std::memory_order_relaxed);
        while (serving.load(std::memory_order_acquire) != my_ticket) {
            __builtin_ia32_pause();
        }
    }
    
    void unlock() {
        serving.fetch_add(1, std::memory_order_release);
    }
};

// 优点：FIFO顺序，公平性好，没有饥饿问题
// 缺点：缓存同步开销较大（所有等待者都读serving）

    3.1.4 MCS锁（可扩展锁）

    // Mellor-Crummey and Scott Lock
class MCSLock {
    struct Node {
        std::atomic<Node*> next{nullptr};
        std::atomic<bool> locked{false};
    };
    
    std::atomic<Node*> tail{nullptr};
    
public:
    void lock(Node* my_node) {
        my_node->next.store(nullptr, std::memory_order_relaxed);
        my_node->locked.store(true, std::memory_order_relaxed);
        
        Node* pred = tail.exchange(my_node, std::memory_order_acq_rel);
        if (pred != nullptr) {
            pred->next.store(my_node, std::memory_order_release);
            while (my_node->locked.load(std::memory_order_acquire)) {
                __builtin_ia32_pause();
            }
        }
    }
    
    void unlock(Node* my_node) {
        Node* succ = my_node->next.load(std::memory_order_acquire);
        if (succ == nullptr) {
            Node* expected = my_node;
            if (tail.compare_exchange_strong(expected, nullptr,
                                                  std::memory_order_release,
                                                  std::memory_order_relaxed)) {
                return;
            }
            while ((succ = my_node->next.load(std::memory_order_acquire)) == nullptr) {
                __builtin_ia32_pause();
            }
        }
        succ->locked.store(false, std::memory_order_release);
    }
};

// 优点：每个等待者自旋在自己的节点上，缓存友好
// 适用：NUMA架构和高竞争场景

    3.2 无锁队列设计

    3.2.1 单生产者-单消费者队列（SPSC）

    // 无锁环形缓冲区
template<typename T, size_t N>
class SPSCQueue {
    static_assert((N & (N - 1)) == 0, "N must be power of 2");
    
    T buffer[N];
    alignas(64) std::atomic<size_t> write_pos{0};
    alignas(64) std::atomic<size_t> read_pos{0};
    
public:
    bool push(T item) {
        size_t w = write_pos.load(std::memory_order_relaxed);
        size_t r = read_pos.load(std::memory_order_acquire);
        
        if ((w + 1) % N == r) {
            return false;  // 队列满
        }
        
        buffer[w] = std::move(item);
        write_pos.store((w + 1) % N, std::memory_order_release);
        return true;
    }
    
    bool pop(T& item) {
        size_t r = read_pos.load(std::memory_order_relaxed);
        size_t w = write_pos.load(std::memory_order_acquire);
        
        if (r == w) {
            return false;  // 队列空
        }
        
        item = std::move(buffer[r]);
        read_pos.store((r + 1) % N, std::memory_order_release);
        return true;
    }
};
    💡 为什么这里可以用relaxed？
    • 生产者：只写 write_pos，读取 read_pos
    • 消费者：只写 read_pos，读取 write_pos
    • acquire-release对：保证了正确的同步
    • 自己的位置：可以用relaxed读取（无竞争）
    📌 伪共享问题（False Sharing）

    使用 alignas(64) 确保 write_pos 和 read_pos 位于不同的缓存行，避免不必要的缓存一致性流量。

    3.2.2 多生产者-单消费者队列（MPSC）

    // Intrusive MPSC Queue (Dmitry Vyukov)
template<typename T>
class MPSCQueue {
    struct Node {
        std::atomic<Node*> next{nullptr};
        T data;
    };
    
    alignas(64) std::atomic<Node*> head;
    alignas(64) Node* tail;
    Node stub;
    
public:
    MPSCQueue() : head(&stub), tail(&stub) {}
    
    void push(T value) {
        Node* node = new Node{nullptr, std::move(value)};
        Node* prev = head.exchange(node, std::memory_order_acq_rel);
        prev->next.store(node, std::memory_order_release);
    }
    
    bool pop(T& result) {
        Node* t = tail;
        Node* next = t->next.load(std::memory_order_acquire);
        
        if (next == nullptr) {
            return false;
        }
        
        result = std::move(next->data);
        tail = next;
        delete t;
        return true;
    }
    
    ~MPSCQueue() {
        while (tail != nullptr) {
            Node* next = tail->next.load(std::memory_order_relaxed);
            delete tail;
            tail = next;
        }
    }
};

    3.2.3 多生产者-多消费者队列（MPMC）

    // Michael-Scott Queue (经典无锁队列)
template<typename T>
class MPMCQueue {
    struct Node {
        std::atomic<Node*> next;
        std::optional<T> data;
        
        Node() : next(nullptr) {}
        Node(T val) : next(nullptr), data(std::move(val)) {}
    };
    
    alignas(64) std::atomic<Node*> head;
    alignas(64) std::atomic<Node*> tail;
    
public:
    MPMCQueue() {
        Node* dummy = new Node();
        head.store(dummy, std::memory_order_relaxed);
        tail.store(dummy, std::memory_order_relaxed);
    }
    
    void enqueue(T value) {
        Node* node = new Node(std::move(value));
        
        while (true) {
            Node* last = tail.load(std::memory_order_acquire);
            Node* next = last->next.load(std::memory_order_acquire);
            
            // 检查tail是否被修改
            if (last == tail.load(std::memory_order_acquire)) {
                if (next == nullptr) {
                    // 尝试插入
                    Node* expected = nullptr;
                    if (last->next.compare_exchange_weak(
                            expected, node,
                            std::memory_order_release,
                            std::memory_order_relaxed)) {
                        // 更新tail
                        tail.compare_exchange_strong(
                            last, node,
                            std::memory_order_release,
                            std::memory_order_relaxed);
                        return;
                    }
                } else {
                    // 帮助其他线程移动tail
                    tail.compare_exchange_strong(
                        last, next,
                        std::memory_order_release,
                        std::memory_order_relaxed);
                }
            }
        }
    }
    
    bool dequeue(T& result) {
        while (true) {
            Node* first = head.load(std::memory_order_acquire);
            Node* last = tail.load(std::memory_order_acquire);
            Node* next = first->next.load(std::memory_order_acquire);
            
            if (first == head.load(std::memory_order_acquire)) {
                if (first == last) {
                    if (next == nullptr) {
                        return false;  // 队列空
                    }
                    // 帮助移动tail
                    tail.compare_exchange_strong(
                        last, next,
                        std::memory_order_release,
                        std::memory_order_relaxed);
                } else {
                    result = std::move(*next->data);
                    if (head.compare_exchange_strong(
                            first, next,
                            std::memory_order_release,
                            std::memory_order_relaxed)) {
                        delete first;
                        return true;
                    }
                }
            }
        }
    }
};

// 注意：这是经典的Michael-Scott算法，存在ABA问题
// 生产环境需要使用hazard pointer或epoch-based回收

    3.3 双重检查锁定（DCLP）

    3.3.1 错误的实现

    // 错误！不要这样写
class Singleton {
    static Singleton* instance;
    static std::mutex mtx;
    
public:
    static Singleton* getInstance() {
        if (instance == nullptr) {           // 第1次检查（数据竞争！）
            std::lock_guard lock(mtx);
            if (instance == nullptr) {       // 第2次检查
                instance = new Singleton();  // 可能重排序！
            }
        }
        return instance;
    }
};
    ⚠️ 为什么错误？

    new Singleton() 实际分为3步：

    1. 分配内存
    2. 调用构造函数
    3. 将指针赋给instance

    编译器可能重排为 1→3→2，导致其他线程看到未初始化的对象！

    3.3.2 正确的实现（C++11）

    // 方法1：使用atomic
class Singleton {
    static std::atomic<Singleton*> instance;
    static std::mutex mtx;
    
public:
    static Singleton* getInstance() {
        Singleton* tmp = instance.load(std::memory_order_acquire);
        if (tmp == nullptr) {
            std::lock_guard lock(mtx);
            tmp = instance.load(std::memory_order_relaxed);
            if (tmp == nullptr) {
                tmp = new Singleton();
                instance.store(tmp, std::memory_order_release);
            }
        }
        return tmp;
    }
};

// 方法2：最简单的方法（推荐）
class Singleton {
public:
    static Singleton& getInstance() {
        static Singleton instance;  // C++11保证线程安全初始化
        return instance;
    }
};

// 方法3：使用call_once
class Singleton {
    static std::unique_ptr<Singleton> instance;
    static std::once_flag flag;
    
public:
    static Singleton* getInstance() {
        std::call_once(flag, []() {
            instance.reset(new Singleton());
        });
        return instance.get();
    }
};

    3.4 引用计数（Reference Counting）

    // 智能指针风格的引用计数
template<typename T>
class SharedPtr {
    struct ControlBlock {
        T* ptr;
        std::atomic<uint32_t> ref_count;
        
        ControlBlock(T* p) : ptr(p), ref_count(1) {}
    };
    
    ControlBlock* ctrl;
    
    void acquire() {
        if (ctrl) {
            ctrl->ref_count.fetch_add(1, std::memory_order_relaxed);
        }
    }
    
    void release() {
        if (ctrl && ctrl->ref_count.fetch_sub(1, std::memory_order_acq_rel) == 1) {
            // 最后一个引用，需要acquire语义确保看到所有之前的修改
            delete ctrl->ptr;
            delete ctrl;
        }
    }
    
public:
    explicit SharedPtr(T* p = nullptr) 
        : ctrl(p ? new ControlBlock(p) : nullptr) {}
    
    SharedPtr(const SharedPtr& other) : ctrl(other.ctrl) {
        acquire();
    }
    
    SharedPtr& operator=(const SharedPtr& other) {
        if (this != &other) {
            release();
            ctrl = other.ctrl;
            acquire();
        }
        return *this;
    }
    
    ~SharedPtr() { release(); }
    
    T* get() const { return ctrl ? ctrl->ptr : nullptr; }
};
    💡 为什么递增用relaxed，递减用acq_rel？
    • 递增：不需要同步（只是表示新的引用）
    • 递减：最后一次递减需要acquire，确保看到所有线程对对象的修改
    • release语义：确保之前的修改对最后一个释放者可见

    3.5 RCU（Read-Copy-Update）

    RCU是Linux内核中广泛使用的同步机制，特别适合读多写少的场景。

    // 简化的RCU示例
template<typename T>
class RCUPointer {
    std::atomic<T*> ptr;
    
public:
    RCUPointer(T* p = nullptr) : ptr(p) {}
    
    // 读者：无锁读取
    T* read() {
        return ptr.load(std::memory_order_acquire);
    }
    
    // 写者：复制-更新
    void update(T* new_ptr) {
        T* old = ptr.exchange(new_ptr, std::memory_order_release);
        
        // 需要等待所有读者完成（实际中使用grace period）
        synchronize_rcu();  // 等待所有读者
        
        delete old;  // 安全删除旧数据
    }
    
    // 简化版的synchronize_rcu（实际更复杂）
    void synchronize_rcu() {
        // 等待所有CPU经历一次上下文切换
        std::this_thread::sleep_for(std::chrono::milliseconds(10));
    }
};

// 使用示例
struct Config {
    int setting1;
    int setting2;
};

RCUPointer<Config> global_config(new Config{10, 20});

// 读者线程：无锁读取
void reader() {
    Config* cfg = global_config.read();
    if (cfg) {
        int s1 = cfg->setting1;  // 安全读取
        int s2 = cfg->setting2;
    }
}

// 写者线程：更新配置
void writer() {
    Config* new_cfg = new Config{30, 40};
    global_config.update(new_cfg);  // 安全更新
}
    📌 RCU的优势
    • 读操作几乎无开销：仅一次acquire load
    • 可扩展性：读者之间完全并行
    • 适用场景：读多写少（如90%以上是读）
    • Linux内核：路由表、进程列表等大量使用

    4.1 性能优化策略

    4.1.1 选择最弱的内存序

    场景 推荐内存序 原因
    计数器递增 relaxed 只需原子性，不需同步
    标志位同步 acquire/release 需要同步但不需全局顺序
    全局顺序保证 seq_cst 需要所有线程看到相同顺序
    引用计数递增 relaxed 不需同步
    引用计数递减 acq_rel 最后一次需要acquire

    4.1.2 批处理优化

    // 不好：频繁的原子操作
std::atomic<int> counter{0};
for (int i = 0; i < 1000000; ++i) {
    counter.fetch_add(1, std::memory_order_seq_cst);  // 很慢！
}

// 好：批处理
thread_local int local_counter = 0;
for (int i = 0; i < 1000000; ++i) {
    ++local_counter;  // 本地累加
}
counter.fetch_add(local_counter, std::memory_order_relaxed);  // 一次性提交

template <typename T>
class AtomicStruct {
    static_assert(sizeof(T) <= sizeof(uint64_t));
    std::atomic<uint64_t> data_;
    
public:
    T load(std::memory_order order = std::memory_order_seq_cst) {
        uint64_t raw = data_.load(order);
        T result;
        std::memcpy(&result, &raw, sizeof(T));
        return result;
    }
    
    void store(T desired, std::memory_order order = std::memory_order_seq_cst) {
        uint64_t raw;
        std::memcpy(&raw, &desired, sizeof(T));
        data_.store(raw, order);
    }
};

class Mutex {
    std::atomic<intptr_t> mu_;  // 用一个原子变量存储状态
    
    void Lock() {
        intptr_t v = mu_.load(std::memory_order_relaxed);
        if ((v & kMuWait) == 0 &&  // 快速路径
            mu_.compare_exchange_strong(v, v | kMuWait,
                                           std::memory_order_acquire,
                                           std::memory_order_relaxed)) {
            return;
        }
        LockSlow();  // 慢速路径
    }
};

    4.5 C++20改进

    4.5.1 atomic wait/notify

    // C++20 新增的等待/通知机制
std::atomic<int> data{0};

// 线程1：等待
void waiter() {
    int old = data.load(std::memory_order_acquire);

        data.wait(old, std::memory_order_acquire);  // 睡眠等待
        old = data.load(std::memory_order_acquire);

}
